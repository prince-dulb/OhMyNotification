# B03 诊断导出规格说明

- **主交付版本**：`v0.5`
- **优先级**：`[B]`
- **规格状态**：`[已确认] plan-v1.0 基线；Phase 0 未决项保持待验证`
- **Phase 0 依赖**：`SP-05 监听可靠性与红魔后台策略`、`SP-07 健康证据与区间精度`、`SP-09 持久化、隐私与性能基线`
- **功能依赖**：A08 本地持久化、A11 健康状态时间轴、A14 性能基线与回归门槛、B02 保留与清理策略
- **被依赖**：`v0.5` 诊断与隐私质量门、后续版本的可复现问题报告

## 1. 目标与范围

本功能只在用户主动操作后，把有界、去隐私化的运行诊断写成一个用户选定位置的 UTF-8 JSON 文件，用于本地排障或由用户自行附到公开 issue。

`[已确认]` 默认导出不得包含通知标题、正文、来源包名、完整 URI、内容 ID、账号、`PendingIntent`、`Intent`、动作令牌、数据库文件、原始异常堆栈、本机路径、设备唯一标识或安装应用清单。

`[已确认]` 导出不是备份。文件不能导回 OMN，不能恢复通知记录，也不能执行任何动作。

### 1.1 本功能包含

- 用户选择诊断时间范围和 Android 系统文档提供方中的保存位置。
- 使用闭合字段白名单生成版本化报告。
- 对同一报告内必须关联的来源使用本次导出专用随机别名。
- 写出前执行结构校验、敏感哨兵扫描和大小约束检查。
- 报告生成、外部写入和失败结果均不阻塞通知摄取事务。
- 成功后显示文件名、大小、生成范围与完整性摘要；只有用户再次明确操作才打开或分享文件。

### 1.2 本功能不包含

- 不自动生成、周期生成、上传、联网、遥测、发邮件或创建 GitHub issue。
- 不导出数据库副本、Room schema、WAL、缓存目录或任意日志目录。
- 不提供“包含原始通知内容”“包含完整 URI”或“包含动作”的危险开关。
- 不持久保存来源别名与真实包名的映射，不跨两次导出复用别名。
- 不请求广泛文件系统权限，不绕过 Storage Access Framework。
- 不用 `WorkManager`、轮询、唤醒锁、精确闹钟或前台服务维持导出。
- 不删除用户已保存到外部位置的旧导出。

## 2. 术语与不变量

| 术语 | 精确定义 |
|---|---|
| `DiagnosticExport` | 一次由用户发起、带固定快照边界的去敏报告生成操作。 |
| `ExportSnapshotBoundary` | 导出开始时已提交诊断序列的最大值；之后新事件不进入本次文件。 |
| 字段白名单 | 格式版本明确列出的唯一可序列化字段；未知领域字段默认不导出。 |
| 来源别名 | `app-001` 形式的本次导出内稳定标识；由随机映射表分配，不能从包名计算。 |
| 私有暂存文件 | OMN 专用缓存子目录中的已去敏候选文件；不等于数据库或原始日志。 |
| 外部目标 | 用户通过 `ACTION_CREATE_DOCUMENT` 选择、由文档提供方返回的 URI。 |
| 完整性摘要 | 文件字节数、记录数和写出后 SHA-256；显示在本机结果页，不要求写回文件自身。 |

全局不变量：

1. 没有用户点击“生成诊断文件”，就没有导出文件、外部 URI 授权或网络流量。
2. 导出器只认识闭合的导出 DTO，不接受 Room entity、`NotificationItem`、`ActionTarget.payload`、framework 对象或原始异常。
3. 任一敏感扫描或结构校验失败时，外部目标不得被标为成功。
4. 同一次文件中的相同 `AppUserKey` 使用同一随机别名；新一次导出重新随机分配。
5. 导出快照之后到达的通知继续正常提交，但不混入本次报告。
6. 用户取消保存、写入失败或进程终止不得修改通知条目、诊断事实、策略、健康证据或动作目标。
7. 外部导出文件归用户和文档提供方管理；B02 清理不得扫描或删除它。

## 3. 用户故事

> 作为遇到漏记、重复或状态异常的用户，我想主动生成一份不含通知内容的诊断文件，以便自己检查或附到公开 issue。

> 作为重视隐私的用户，我希望文件在保存前就已经完成去敏，而且应用不会偷偷上传它。

> 作为仍在接收通知的用户，我希望导出期间监听与持久化继续工作，不因生成报告丢掉新通知。

## 4. 输入契约

以下是逻辑契约，不是数据库 schema。

### 4.1 `PrepareDiagnosticExportRequest`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `requestId` | `RequestId` | 是 | 当前进程唯一。 |
| `requestedAt` | `InstantUtc` | 是 | 用户点击生成时刻。 |
| `range` | `ClosedRange<InstantUtc>` | 是 | 用户可见诊断时间范围；开始不得晚于结束。 |
| `sections` | `NonEmptySet<DiagnosticSection>` | 是 | 只允许第 4.2 节闭合值。 |
| `runtimeSessionId` | `RuntimeSessionId` | 是 | 防止旧页面请求跨进程继续。 |
| `formatVersion` | `DiagnosticFormatVersion` | 是 | 首版固定为 `OMN_DIAGNOSTIC_JSON_V1`。 |

默认时间范围为最近 24 小时，但只是前台表单默认值，不建立 24 小时保留规则。用户可以缩短或扩展到当前仍有诊断事实的范围。

### 4.1.1 `WriteDiagnosticExportRequest`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `preparedExportId` | `PreparedExportId` | 是 | 指向当前进程中已通过隐私校验的私有暂存文件。 |
| `runtimeSessionId` | `RuntimeSessionId` | 是 | 必须与准备阶段一致。 |
| `destination` | `CreateDocumentGrant` | 是 | 当前系统文件选择器返回的单次外部目标。 |
| `requestedAt` | `InstantUtc` | 是 | 用户确认保存位置的时刻。 |

准备与写出分成两步：只有候选报告存在且已通过隐私校验后才打开系统文件选择器，因此无数据、结构失败或敏感扫描失败都不会先创建外部空文件。

### 4.2 `DiagnosticSection`

| 值 | 允许内容 |
|---|---|
| `BUILD_AND_DEVICE` | OMN 版本/commit、release 类型、Android 版本、系统构建、设备型号、ABI、时区 ID；不含序列号、Android ID 或广告标识。 |
| `RUNTIME_CONFIGURATION` | 五个健康维度、状态通知承载模式、策略修订、排除来源数量、查看筛选是否启用；不含来源真名或关键词。 |
| `HEALTH_EVIDENCE` | 有界健康事实的时间、facet、状态枚举、会话/连接导出别名。 |
| `INGESTION_SUMMARY` | 回调、接纳、排除、创建、更新、移除、失败和队列峰值计数；可含来源随机别名的聚合。 |
| `FAILURE_SUMMARY` | 固定错误码、计数、首次/最近时间和重试分类；不含异常原文。 |
| `ACTION_SUMMARY` | 动作层与失败枚举的聚合计数；不含条目标题、URI、内容 ID、目标 payload 或令牌。 |
| `PERFORMANCE_SUMMARY` | A14 已定义指标的数值、单位、场景和测量方法版本；不含原始工具路径。 |
| `RETENTION_SUMMARY` | B02 策略版本、诊断上限状态、条目/诊断/缓存聚合占用；不含条目内容。 |

`sections` 初始默认全选。关闭某节只减少报告内容，不改变诊断事实或 B02 保留策略。

### 4.3 `CreateDocumentGrant`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `uri` | `DocumentUri` | 是 | 只在当前操作内存中使用；不进入诊断文件和普通日志。 |
| `displayName` | `String` | 是 | 建议名 `omn-diagnostic-YYYYMMDD-HHmmss.json`；由系统文件选择器确认。 |
| `mimeType` | `MimeType` | 是 | 固定为 `application/json`。 |
| `grantMode` | `GrantMode` | 是 | 必须具有当前操作写授权；不请求目录级扫描能力。 |
| `createdForRequestId` | `RequestId` | 是 | 必须与当前请求一致，防止复用旧 URI。 |

OMN 只写入本次 `ACTION_CREATE_DOCUMENT` 返回的目标，不接受设置页粘贴的任意文件路径。

## 5. 输出格式契约

### 5.1 顶层 `DiagnosticExportDocumentV1`

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `formatId` | `String` | 是 | 固定为 `oh-my-notification-diagnostic`。 |
| `formatVersion` | `Int` | 是 | 固定为 1。 |
| `generatedAt` | `InstantUtc` | 是 | 实际完成候选文件的时间。 |
| `rangeStart` / `rangeEnd` | `InstantUtc` | 是 | 等于请求范围。 |
| `snapshotMaxSequence` | `StableSequence` | 是 | 本次快照边界。 |
| `sections` | `List<DiagnosticSectionPayload>` | 是 | 只出现用户请求且成功生成的节，顺序固定。 |
| `recordCounts` | `Map<DiagnosticSection, NonNegativeLong>` | 是 | 每节序列化记录数。 |
| `truncation` | `DiagnosticTruncationSummary` | 是 | 因 B02 上限或文件安全上限缺少记录时明确说明。 |
| `privacyProfile` | `String` | 是 | 固定为 `DEFAULT_REDACTED_V1`。 |

JSON 使用 UTF-8、稳定字段名和稳定枚举值；字段顺序只为可读性固定，不参与语义。时间一律为 UTC ISO 8601，界面可另按设备时区显示。

### 5.2 允许的记录字段

所有明细记录只能由以下基础字段组合：

- `occurredAt`、可选 `durationMs`；
- 固定领域枚举与错误码；
- 非负计数、字节数、比例和带单位性能值；
- 本次导出随机 `sourceAlias`、`sessionAlias`、`connectionAlias`；
- 策略、格式、解析器、测量方法和构建版本；
- 去敏布尔状态与完整性标志。

以下字段在 DTO 类型中不存在，并由输出扫描再次阻断：

- `title`、`body`、`text`、`bigText`、`subText`、原始通知渠道名；
- 来源包名、应用标签、账号、UP 主名、设备用户名；
- 完整 URI、scheme payload、内容 ID、BV/AV 号、动态 ID、直播间 ID；
- `PendingIntent`、`Intent`、`Bundle`、`Parcel`、Binder 令牌、组件 extras；
- 本机文件路径、SDK 路径、数据库名、SQL 参数原值；
- 原始异常消息、堆栈、日志行、截图和数据库行；
- 设备序列号、`ANDROID_ID`、广告 ID、IMEI、MAC、IP。

### 5.3 `DiagnosticExportResult`

| 状态 | 必填输出 | 含义 |
|---|---|---|
| `EXPORTED` | 文件名、字节数、SHA-256、记录数、时间范围、完成时刻 | 外部流完整关闭且本地复核通过。 |
| `USER_CANCELED` | 完成时刻 | 用户取消文件选择或结果页；没有成功文件。 |
| `NO_DIAGNOSTIC_DATA` | 请求范围、完成时刻 | 范围内无可导出的事实；不创建空成功文件。 |
| `STALE_REQUEST` | 完成时刻 | 进程会话或目标授权与请求不匹配。 |
| `FAILED` | `DiagnosticExportFailure`、完成时刻、`partialTargetPossible` | 未完成；不能显示“已导出”。 |

`EXPORTED` 的 SHA-256 在外部写入完成后由同一已去敏字节流计算并在本机结果页显示。哈希不上传，不用于跨文件关联。

## 6. 生成状态机与精确规则

```text
IDLE
  → 用户配置范围与章节 → SNAPSHOTTING
      ├─ 无数据 → NO_DIAGNOSTIC_DATA
      └─ 取得边界 → GENERATING_PRIVATE_STAGE
           ├─ DTO/大小失败 → FAILED
           └─ 生成完成 → VALIDATING
                ├─ 结构/敏感扫描失败 → FAILED
                └─ 通过 → 系统文件选择器
                     ├─ 取消 → USER_CANCELED + 清理暂存
                     └─ 返回本次写授权 → WRITING_EXTERNAL_TARGET
                          ├─ 写入/关闭失败 → FAILED
                          └─ 完成复核 → EXPORTED
```

规则顺序：

1. 验证准备请求的当前 `runtimeSessionId`、范围和章节。
2. 读取 B02 已锁定的诊断边界，并取得当前已提交最大诊断序列。
3. 只查询范围内且序列不大于快照边界的白名单投影；读取使用有限页或流。
4. 在内存中建立本次随机别名表；只把别名写入 DTO。
5. 将 JSON 流式写入 OMN 专用私有暂存文件，同时统计记录数、字节数和候选 SHA-256。
6. 对完整暂存文件执行 JSON schema/字段白名单校验、禁止字段名检查和版本化敏感哨兵扫描。
7. 任一校验失败时不写外部目标，返回分类失败并清理本次私有暂存文件。
8. 校验通过后才打开系统文件选择器；用户取消则清理暂存并结束。取得授权后验证写出请求与准备阶段属于同一进程和 `preparedExportId`，再流式复制到目标；通知摄取继续使用独立串行写事务。
9. 外部流成功关闭后复核已写字节数；只有一致才返回 `EXPORTED`。
10. 成功或失败后清理本次私有暂存文件。若进程中止遗留，只在下次应用启动或下一次导出时清理 OMN 专用暂存子目录内、符合固定命名与所有权规则的文件，不扫描外部存储。

### 6.1 大小与截断

- 导出只读取 B02 已有的有界诊断，不通过扫描全部 `NotificationItem` 构造新明细。
- `SP-09` 必须锁定单文件安全上限和每节最大记录数；未锁定时 B03 不得标记完成。
- 达到安全上限时，只能按 `occurredAt DESC + 稳定序列 DESC` 保留范围内较新诊断，并在 `truncation` 写明省略的节、数量与原因。
- 截断不能删改数据库事实，也不能用“完整”字样误导用户。
- `BUILD_AND_DEVICE`、隐私配置和截断摘要不能被静默截掉；若连最小报告都放不下则失败。

### 6.2 外部目标失败

- 写入失败时尝试关闭流，并仅对“本次创建且仍持有授权”的目标请求回滚删除。
- 文档提供方不支持删除或删除失败时，`partialTargetPossible=true`，结果页明确提示目标位置可能留有不完整文件，供用户自行处理。
- OMN 不扫描目标目录确认旧文件，也不删除任何非本次请求创建的文件。

## 7. 权限与生命周期边界

- 使用 Android Storage Access Framework；不请求 `MANAGE_EXTERNAL_STORAGE` 或传统广泛存储权限。
- 通知使用权、`POST_NOTIFICATIONS` 和状态渠道不授权导出；导出必须来自应用内前台用户动作。
- 页面进入后台时允许当前短操作继续到安全检查点；进程被系统终止则操作结束，不由后台任务自动恢复。
- 进程重建后旧 `CreateDocumentGrant` 与请求均失效，用户必须重新发起。
- 设备重启不恢复未完成导出；已保存外部文件由文档提供方保留。
- 监听断连或数据库降级时仍可导出已有诊断，但报告必须含对应状态和快照边界，不能声称覆盖未知区间。
- 新通知在导出期间继续提交；只要序列大于快照边界就进入下一次导出。

## 8. Given / When / Then 验收条件

### AC-B03-01 只有主动操作才导出

- Given 用户从未点击生成诊断
- When 应用运行、息屏、重启或收到通知
- Then 不创建诊断文件、不请求外部 URI、不上传数据且不增加周期工作

### AC-B03-02 默认文件不含通知内容

- Given 本地诊断关联的通知含唯一哨兵标题、正文、URI、内容 ID、动作和账号
- When 用户生成默认诊断
- Then 导出 JSON 及结果元数据均不含任何哨兵或可逆变体
- And 只出现本次随机来源别名与允许枚举

### AC-B03-03 同文件可关联、跨文件不可关联

- Given 同一来源在一个范围内有多条诊断
- When 连续生成两次文件
- Then 每个文件内部该来源别名一致
- And 两个文件的别名映射独立，不能从包名哈希反推或稳定关联

### AC-B03-04 快照不阻塞新通知

- Given 导出已取得 `snapshotMaxSequence=N`
- When 导出过程中有新通知提交为序列 N+1
- Then 新通知正常持久化，不进入本次文件
- And 下一次覆盖该时间范围的导出可以包含其去敏诊断

### AC-B03-05 取消保存

- Given 候选报告已通过隐私校验且用户已打开系统文件选择器
- When 用户取消
- Then 返回 `USER_CANCELED`，清理私有暂存，不生成成功文件、不修改任何本地事实

### AC-B03-06 无数据范围

- Given 请求范围内没有白名单诊断事实
- When 生成
- Then 返回 `NO_DIAGNOSTIC_DATA`，不打开系统文件选择器，也不把只有空数组的文件标为成功

### AC-B03-07 敏感扫描失败

- Given 测试夹具让未知字段或敏感哨兵进入候选 DTO
- When 校验暂存文件
- Then 返回 `FAILED/PRIVACY_VALIDATION_FAILED`
- And 外部目标不被写入，错误日志也不输出该敏感值

### AC-B03-08 外部写入失败

- Given 私有暂存已通过验证
- When 文档提供方在写入或关闭时失败
- Then 不显示“已导出”
- And 只回滚本次创建目标；无法回滚时明确显示可能存在不完整文件

### AC-B03-09 文件完整性

- Given 外部写入成功
- When 返回结果
- Then JSON 可由严格解析器读取、版本字段正确、记录数与内容一致
- And 本机结果页显示字节数与写出字节流 SHA-256

### AC-B03-10 不导出来源包名和安装列表

- Given 多应用产生诊断且设备安装其他应用
- When 生成全部章节
- Then 文件只含随机来源别名和来源数量
- And 不含来源包名、应用标签或完整安装应用清单

### AC-B03-11 10,000 条历史边界

- Given 有 10,000 条长期历史但诊断按 B02 保持有界
- When 生成最大允许范围报告并同时接收测试通知
- Then 不扫描或加载全部长期条目，摄取结果无漏记、重复或超预算阻塞

### AC-B03-12 不自动分享

- Given 导出成功
- When 用户不点击后续“打开”或“分享”
- Then OMN 不启动其他应用、不上传文件、不持久保存目标 URI

## 9. 错误状态

| `DiagnosticExportFailure` | 用户可见结果 | 系统行为 |
|---|---|---|
| `INVALID_RANGE` | “开始时间不能晚于结束时间。” | 保持表单，不打开文件选择器。 |
| `STALE_DOCUMENT_GRANT` | “保存授权已失效，请重新选择位置。” | 不复用旧 URI。 |
| `DIAGNOSTIC_QUERY_FAILED` | “无法读取诊断数据。” | 不把空结果伪装成功；通知摄取继续。 |
| `POLICY_NOT_LOCKED` | “诊断边界尚未完成真机验证。” | 阻断 B03 完成声明，不使用魔法数字。 |
| `PRIVATE_STAGE_FAILED` | “无法生成安全暂存文件。” | 清理本次暂存；不写外部目标。 |
| `PRIVACY_VALIDATION_FAILED` | “隐私检查未通过，文件未导出。” | 阻断写出，记录无敏感值错误枚举。 |
| `REPORT_TOO_LARGE` | “诊断文件超过安全上限。” | 按已锁定截断规则重试一次；最小报告仍超限则失败。 |
| `DESTINATION_WRITE_FAILED` | “保存失败。” | 关闭流并回滚本次目标；不能回滚时提示可能有不完整文件。 |
| `DESTINATION_CLOSE_FAILED` | “文件可能未完整写入。” | 不返回成功；按同一回滚规则处理。 |
| `INTEGRITY_MISMATCH` | “导出完整性检查失败。” | 不显示成功，不自动上传或重试。 |
| `UNKNOWN_EXPORT_FAILURE` | “诊断导出失败。” | 保留去敏枚举；等待用户明确重试。 |

所有重试都由用户操作触发；禁止后台循环重试。

## 10. 交互与无障碍

1. 设置页的“生成诊断文件”进入摘要页，先展示默认不包含的敏感类别、将包含的章节、时间范围和预计记录数。
2. 用户确认后才打开系统文件选择器；应用不自制文件浏览器。
3. 生成中显示可取消的前台进度，取消后在安全点停止；不虚报即时取消已完成的外部写入。
4. 成功页显示文件名、位置由用户选择、大小、时间范围、是否截断和 SHA-256；“打开”“分享”是两个后续明确动作。
5. 失败页说明是否可能存在不完整目标，不能只显示通用 Toast。
6. 控件至少 48dp，TalkBack 朗读章节、隐私排除、范围、进度、截断与结果。
7. 最大字体、横竖屏、分屏、深浅色和减少动态效果下均可完成选择、取消与保存。

## 11. 隐私、安全与性能约束

- 导出路径完全本地，OMN 自身零网络、零遥测、零远程解析。
- 白名单 DTO 与禁止字段扫描采用双重防线；反射式“把整个对象转 JSON”不允许。
- 来源别名使用每次导出新随机映射，不使用稳定包名哈希。
- 暂存目录固定在应用私有缓存子目录；文件名不含包名、标题、时间轴内容或用户标识。
- release 日志只记录请求别名、状态枚举、记录数、字节数和耗时，不记录 URI、路径或导出内容。
- 读取与写出均分页/流式；内存峰值不随 10,000 条长期历史线性增长。
- 导出调度优先级低于通知快照复制与摄取事务；不得占用监听回调线程或摄取单消费者。
- 导出不启动后台常驻组件；页面关闭、没有用户操作时没有周期查询、写盘、唤醒或网络。
- 单文件大小、每节记录数、页大小、导出耗时、峰值 PSS 和对摄取延迟的绝对预算由 `SP-09`/A14 锁定；无解释回退超过 10% 阻断版本。

- SAF 成功、用户取消、授权失效、写失败、关闭失败、回滚失败和进程重建测试。

### 12.2 红魔 11 Pro+ 真机测试

- release 构建通过系统文件选择器分别保存到本机文档和至少一个可用外部文档提供方；不要求安装新的提供方。

- 在 100 条突发和持续摄取期间导出，逐条对账无漏记、重复、事务延迟越界或状态摘要错误。
- 在 10,000 条长期历史与 B02 最大诊断边界下记录耗时、峰值 PSS、读取页数、暂存/外部字节和数据库影响。
- 覆盖文件选择取消、文档提供方拒写、进程终止、设备重启与剩余私有暂存清理。

## 13. Phase 0 Spike 与决策门

### 13.1 必须回答

1. `SP-05/SP-07` 的哪些健康与监听事实足够排障且不泄露通知内容？
2. `SP-09` 锁定的诊断保留上限、单文件上限、分页大小与暂存清理边界是什么？
3. 每个白名单字段对哪类问题有实际解释价值；无价值字段必须删除。
4. 来源随机别名是否足以关联同文件事件，同时避免跨文件识别？
5. 文件生成对摄取延迟、PSS、CPU 和写盘的影响是否满足绝对预算？
6. 目标文档提供方部分写入时能否可靠回滚；不能时用户文案如何准确表达残留风险？

### 13.2 证据产物

- `DiagnosticExportDocumentV1` JSON schema 与版本化去隐私夹具；
- 全禁止字段哨兵扫描报告；
- SAF 成功、取消、失败、部分目标和进程终止矩阵；
- 100 条并发摄取与 10,000 条历史性能结果；
- 暂存文件生命周期与所有权边界；
- 带单位的单文件、记录数、耗时、PSS、写盘和摄取影响预算。

### 13.3 决策门

- **GO**：报告只含有用白名单字段；敏感扫描通过；无自动生成/上传；并发摄取正确；SAF 失败可解释；全部绝对预算和 10% 门通过。
- **REDIRECT**：某节隐私风险高于排障价值、文档提供方无法稳定写入，或性能需要更小范围；删除该节、收窄格式或调整交互后先更新规格。
- **STOP**：有用诊断只能依赖正文、完整目标、稳定来源标识、数据库导出、自动上传，或报告生成必须阻塞监听/依赖常驻后台工作。

B03 只有在格式、白名单、上限、SAF 失败语义和性能预算均由 Phase 0 锁定，自动化/红魔真机测试通过，且默认导出敏感扫描为零命中后，才可在 `v0.5` 标记完成。
