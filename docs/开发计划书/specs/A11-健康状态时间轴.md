# A11 健康状态时间轴规格说明

- **主交付版本**：`v0.3`
- **优先级**：`[A]`
- **规格状态**：`[候选] plan-v1.0`
- **Phase 0 依赖**：`SP-05 监听可靠性与红魔后台策略`、`SP-07 健康证据与区间精度`
- **功能依赖**：A01 首次授权与全量监听、A03 通知事件采集、A08 本地持久化、A06 稳定排序
- **被依赖**：A10 常驻状态通知、A13 B 站端到端真机验收、A14 性能基线与回归门槛

## 1. 目标与范围

本功能把可验证的监听、权限和进程事实派生为应用内健康视图：

- 左侧时间轨道用蓝色实线表示 `CONFIRMED_RUNNING`；
- 黄色虚线表示 `UNCONFIRMED`；
- 文字和无障碍语义同步说明每段状态；
- 通知使用权、`POST_NOTIFICATIONS`、状态通知渠道、监听连接和进程证据分别显示当前状态与最近观察时间。

`[已确认]` 蓝色表示“这段时间有足够正面证据确认通知监听在运行”，黄色表示“证据不足”。黄色不是“已知停机”，也不是精确漏记区间。应用无法在自己突然被系统终止的瞬间写下停止事实，因此不得虚构准确停机时刻。

### 1.1 本功能不做

- 不提供没有证据支持的 `STOPPED`、`HEALTHY_FOREVER` 或“绝无漏记”状态。
- 不因通知使用权已授予、状态通知存在、渠道启用或进程当前打开而单独把时间轴涂蓝。
- 不用周期心跳、轮询、唤醒锁、精确闹钟或高频 `WorkManager` 增加蓝色覆盖。
- 不把健康区间作为通知记录的替代物；区间与通知条目沿同一 UTC 时间轴组合显示，但事实来源独立。
- 不把应用外状态通知残留当作进程或监听仍在运行的证据。

## 2. 术语与事实维度

### 2.1 五个独立健康维度

| `HealthFacet` | 状态类型 | 允许状态 | 精确含义 |
|---|---|---|---|
| `LISTENER_ACCESS` | `ListenerAccessState` | `GRANTED`、`NOT_GRANTED`、`UNKNOWN` | 系统是否授予通知使用权；不等于监听连接。 |
| `STATUS_PERMISSION` | `StatusPermissionState` | `NOT_REQUESTED`、`GRANTED`、`DENIED`、`UNKNOWN` | `POST_NOTIFICATIONS`；只控制应用通知可见性。 |
| `STATUS_CHANNEL` | `StatusChannelState` | `NOT_CREATED`、`ENABLED`、`DISABLED`、`UNKNOWN` | 固定“运行状态”渠道；只控制该渠道。 |
| `LISTENER` | `ListenerConnectionState` | `NEVER_OBSERVED`、`CONNECTED`、`DISCONNECTED` | 当前会话真实监听连接事实。 |
| `PROCESS` | `ProcessEvidenceState` | `CURRENT_SESSION_ACTIVE`、`NO_CURRENT_SESSION_EVIDENCE` | 当前代码会话或历史无当前会话证据。 |

### 2.2 证据与区间术语

| 术语 | 定义 |
|---|---|
| **正面监听证据** | `LISTENER_CONNECTED`、同一连接的 `NOTIFICATION_CALLBACK`、成功完成的 `RECOVERY_COMPLETED`。这些事实证明证据发生时监听链路在工作。 |
| **明确边界证据** | `LISTENER_DISCONNECTED`、`ACCESS_OBSERVED(NOT_GRANTED)`。它们结束当前可确认连接；之后不自动判为已停机，只进入未确认。 |
| **进程事实** | `PROCESS_STARTED`、`NORMAL_STOP`。它们说明进程会话边界，但单独不能证明监听连接。 |
| **实时投影** | 当前进程内存仍确认同一监听连接为 `CONNECTED` 时，从该连接最后正面证据投影到查询时刻的临时蓝段。它不是已持久化历史结论。 |
| **历史空档** | 没有足够正面证据覆盖的查询时间，包括突然终止前后无法定位的时段；统一为 `UNCONFIRMED`。 |

## 3. 用户故事

> 作为依赖 OMN 保存通知的用户，我想沿通知时间轴看到哪些时段有确切监听证据、哪些时段无法确认，以便判断一段时间内的空白究竟是没有通知还是应用可能没有工作。

> 作为排障用户，我想分别看到通知使用权、状态通知权限、渠道、监听连接和当前进程证据，以便针对真正有问题的系统设置采取动作。

> 作为关心耗电的用户，我接受时间轴出现诚实的黄色未知区间，而不希望应用为了把轨道涂蓝而周期唤醒手机。

## 4. 输入契约

### 4.1 `HealthEvidenceRecord`

| 字段 | 逻辑类型 | 必填 | 约束 |
|---|---|---:|---|
| `evidenceId` | `EvidenceId` | 是 | 不变内部标识。 |
| `evidenceSequence` | `StableSequence` | 是 | 同一安装内单调递增；同一 UTC 时间下决定事实处理顺序。 |
| `runtimeSessionId` | `RuntimeSessionId` | 是 | 每次进程启动生成新值。 |
| `listenerConnectionId` | `ConnectionId?` | 否 | `LISTENER_CONNECTED`、`LISTENER_DISCONNECTED`、`NOTIFICATION_CALLBACK`、`RECOVERY_COMPLETED` 必填。 |
| `kind` | `HealthEvidenceKind` | 是 | 允许值见 4.2。 |
| `facet` | `HealthFacet` | 是 | 必须与 `kind` 匹配。 |
| `value` | `HealthFactValue` | 是 | 离散枚举；不得包含通知正文或动作。 |
| `occurredAt` | `InstantUtc` | 是 | UTC 壁钟时间。 |
| `occurredElapsed` | `MonotonicTime?` | 否 | 同一进程内校验壁钟跳变；不得跨进程比较。 |

### 4.2 `HealthEvidenceKind`

允许值及字段约束：

| 值 | `facet` | `value` | 连接 ID |
|---|---|---|---|
| `PROCESS_STARTED` | `PROCESS` | `CURRENT_SESSION_ACTIVE` | 空 |
| `NORMAL_STOP` | `PROCESS` | `NO_CURRENT_SESSION_EVIDENCE` | 空 |
| `LISTENER_CONNECTED` | `LISTENER` | `CONNECTED` | 必填，新连接 ID |
| `LISTENER_DISCONNECTED` | `LISTENER` | `DISCONNECTED` | 必填，必须引用被断开的连接 |
| `NOTIFICATION_CALLBACK` | `LISTENER` | `CONNECTED` | 必填 |
| `RECOVERY_COMPLETED` | `LISTENER` | `CONNECTED` | 必填 |
| `ACCESS_OBSERVED` | `LISTENER_ACCESS` | `GRANTED`、`NOT_GRANTED` 或 `UNKNOWN` | 空 |
| `STATUS_PERMISSION_OBSERVED` | `STATUS_PERMISSION` | `NOT_REQUESTED`、`GRANTED`、`DENIED` 或 `UNKNOWN` | 空 |
| `STATUS_CHANNEL_OBSERVED` | `STATUS_CHANNEL` | `NOT_CREATED`、`ENABLED`、`DISABLED` 或 `UNKNOWN` | 空 |

### 4.3 `HealthTimelineQuery`

| 字段 | 逻辑类型 | 必填 | 约束 |
|---|---|---:|---|
| `rangeStart` | `InstantUtc` | 是 | 查询半开区间起点。 |
| `rangeEnd` | `InstantUtc` | 是 | 必须大于 `rangeStart`；查询半开区间终点。 |
| `observedNow` | `InstantUtc` | 是 | 本次派生时刻；不得由 UI 自行无限刷新。 |
| `currentRuntimeSessionId` | `RuntimeSessionId?` | 否 | 当前进程存在时提供。 |
| `currentConnectionId` | `ConnectionId?` | 否 | 当前内存监听为 `CONNECTED` 时提供；否则为空。 |
| `currentListenerState` | `ListenerConnectionState` | 是 | `NEVER_OBSERVED`、`CONNECTED`、`DISCONNECTED`。 |
| `loadedItemRange` | `ClosedRange<InstantUtc>?` | 否 | 与当前分页通知窗口组合显示时提供；不改变健康事实查询结果。 |

证据查询必须覆盖 `rangeStart` 之前最近一条与各 facet/当前连接相关的事实，用于确定区间起点状态；不能只查区间内记录后把边界猜成蓝色。

## 5. 输出契约

### 5.1 `HealthInterval`

| 字段 | 逻辑类型 | 必填 | 约束 |
|---|---|---:|---|
| `start` | `InstantUtc` | 是 | 大于等于查询起点。 |
| `end` | `InstantUtc` | 是 | 大于 `start`、小于等于查询终点；半开区间。 |
| `state` | `HealthIntervalState` | 是 | 仅 `CONFIRMED_RUNNING` 或 `UNCONFIRMED`。 |
| `evidenceRefs` | `List<EvidenceId>` | 是 | 支撑边界的最小证据引用；黄色允许为空。 |
| `connectionId` | `ConnectionId?` | 否 | 蓝色区间必填且只属于一个连接；黄色为空。 |
| `isLiveProjection` | `Boolean` | 是 | 仅当前会话投影段为 `true`。 |
| `explanation` | `HealthIntervalExplanation` | 是 | `BETWEEN_POSITIVE_EVIDENCE`、`UNTIL_EXPLICIT_DISCONNECT`、`CURRENT_CONNECTED_PROJECTION`、`INSUFFICIENT_EVIDENCE`。 |

### 5.2 `HealthFacetSummary`

| 字段 | 逻辑类型 | 必填 | 说明 |
|---|---|---:|---|
| `facet` | `HealthFacet` | 是 | 五个维度之一。 |
| `state` | 对应 facet 状态类型 | 是 | 不把五个维度压成一个 Boolean。 |
| `lastObservedAt` | `InstantUtc?` | 否 | 没有该维度事实时为空。 |
| `isCurrentSessionObservation` | `Boolean` | 是 | 是否来自当前进程会话。 |
| `action` | `HealthRepairAction?` | 否 | `OPEN_LISTENER_ACCESS_SETTINGS`、`OPEN_APP_NOTIFICATION_SETTINGS`、`OPEN_STATUS_CHANNEL_SETTINGS`、`USER_REFRESH` 或空。 |
| `messageKey` | `HealthMessageKey` | 是 | 界面资源键；不得直接包含敏感通知内容。 |

### 5.3 `HealthTimelineModel`

| 字段 | 逻辑类型 | 必填 | 说明 |
|---|---|---:|---|
| `range` | `HalfOpenRange<InstantUtc>` | 是 | 等于请求范围。 |
| `intervals` | `List<HealthInterval>` | 是 | 按时间升序、无重叠、无空洞，完整覆盖请求范围。 |
| `facets` | `List<HealthFacetSummary>` | 是 | 恰好五个维度，每个一次。 |
| `lastPositiveEvidenceAt` | `InstantUtc?` | 否 | 最近实际正面监听证据；实时投影不能把它改成 `observedNow`。 |
| `hasLiveProjection` | `Boolean` | 是 | 当前模型是否含临时投影蓝段。 |
| `derivationRevision` | `StableSequence` | 是 | 输入证据或当前实时状态变化才递增。 |

## 6. 确定性派生规则

### 6.1 事实预处理

1. 丢弃不在请求相关时间范围且不是边界前置事实的记录；不修改持久事实。
2. 按 `occurredAt ASC, evidenceSequence ASC` 形成全序。同一会话内如 UTC 时间与 `occurredElapsed` 顺序冲突，保留稳定序列并产生“壁钟调整”诊断，不把区间倒置。
3. 连接证据必须同时匹配 `runtimeSessionId + listenerConnectionId`；相同连接 ID 跨会话出现视为无效证据并进入错误状态。
4. `STATUS_PERMISSION` 和 `STATUS_CHANNEL` 记录只更新 facet 卡，不参与蓝黄监听区间。
5. `PROCESS_STARTED` 单独不产生蓝色；旧会话的 `CONNECTED` 也不能给新会话涂蓝。

### 6.2 蓝色区间生成

先将整个查询范围初始化为 `UNCONFIRMED`，再只用下列规则覆盖为 `CONFIRMED_RUNNING`：

1. 对每个 `runtimeSessionId + listenerConnectionId`，取按全序排列的正面监听证据。
2. 同一连接任意两条相邻正面证据之间，若中间没有该连接的断连或 `LISTENER_ACCESS=NOT_GRANTED`，区间为蓝色，解释为 `BETWEEN_POSITIVE_EVIDENCE`。
3. 若一条正面证据之后收到同一连接明确 `LISTENER_DISCONNECTED`，且中间没有更早负面边界，则从该正面证据到断连时刻为蓝色，解释为 `UNTIL_EXPLICIT_DISCONNECT`；断连时刻之后为黄色。
4. 若当前内存满足：`currentRuntimeSessionId` 与最后正面证据会话相同、`currentConnectionId` 相同、`currentListenerState=CONNECTED`，则从最后正面证据投影到 `min(observedNow, rangeEnd)` 为蓝色，`isLiveProjection=true`。
5. `ACCESS_OBSERVED(NOT_GRANTED)` 在其发生时结束所有活动连接的蓝色候选；之后保持黄色，直到新会话/新连接的正面证据重新建立覆盖。
6. 上一会话最后正面证据后没有断连事实且当前进程已经是新会话时，最后证据到下一证据之间保持黄色；不得把突然终止时刻猜在中间。
7. 只有一个历史正面证据、之后既无明确断连也非当前实时连接时，该证据之后不形成有长度的蓝段。
8. 多条蓝段重叠只可能来自无效输入；输出按证据全序保留可解释连接并产生诊断，不合并不同连接为一个“更健康”区间。

### 6.3 区间规范化

1. 将蓝色候选裁剪到请求范围。
2. 剩余空白全部输出黄色 `UNCONFIRMED`，解释为 `INSUFFICIENT_EVIDENCE`。
3. 相邻且状态、连接 ID、实时投影标志和解释相同的区间合并；不同解释不合并，以保留可说明边界。
4. 输出必须完整覆盖 `[rangeStart, rangeEnd)`，任意时刻恰好属于一个区间。
5. 视图按最新在上渲染不改变 `intervals` 的升序领域契约；UI 自行按时间轴方向映射。

### 6.4 当前 facet 判定

- 每个 facet 取全序中最后一个已观察事实；没有事实时使用该 facet 的 `UNKNOWN`/`NEVER_OBSERVED`/`NO_CURRENT_SESSION_EVIDENCE`。
- 当前内存连接只可覆盖 `LISTENER` facet 的实时显示，不写成新的历史事实；真实连接/断连回调仍须持久化。
- `POST_NOTIFICATIONS=DENIED` 或渠道 `DISABLED` 不改变 `LISTENER=CONNECTED`，只显示“应用外状态不可见”。
- 通知使用权为 `GRANTED` 但监听没有当前连接时，facet 分别显示“已授权”和“未确认连接”。
- 状态通知存在本身不进入 `HealthEvidenceKind`。

## 7. 交互与时间轴组合

```text
分页通知窗口 + 对应 UTC 时间范围
  → 查询健康证据（含范围前置事实）
  → 纯函数派生连续蓝/黄区间
  → Compose 时间轴按设备时区绘制
      ├─ 蓝色实线 + “已确认运行”语义
      └─ 黄色虚线 + “未确认运行”语义

用户点击轨道或顶部健康摘要
  → 打开健康详情
  → 分别显示五个 facet、最近观察时间、证据说明和修复入口
```

轨道不抢占通知条目的 TalkBack 节点。连续同状态视觉段可合并绘制，但无障碍描述必须能说明当前可见通知范围内有哪些已确认/未确认时段。点击健康详情入口至少 48dp；颜色、线型、文字和语义四者同时存在。

## 8. Given / When / Then 验收条件

1. **连接后实时投影**<br>
   Given 当前会话收到 `LISTENER_CONNECTED` 且内存仍为同一 `CONNECTED`，When 查询到当前时刻，Then 从连接证据到 `observedNow` 为蓝色实时投影，且 `lastPositiveEvidenceAt` 仍等于连接证据时间。

2. **正面证据之间确认**<br>
   Given 同一连接在 10:00 连接、10:05 收到通知回调，When 查询 09:55–10:10 且当前连接已不再可投影，Then 10:00–10:05 为蓝色，其余没有证据覆盖的时段为黄色。

3. **明确断连边界**<br>
   Given 同一连接 10:00 有正面证据、10:07 收到断连，When 查询该范围，Then 10:00–10:07 为蓝色，10:07 后为黄色，不产生 `STOPPED` 状态。

4. **突然终止**<br>
   Given 旧会话最后正面证据为 10:00、没有断连，下一进程会话 11:00 启动，When 查询 10:00–11:00，Then 该空档为黄色，不猜测进程何时死亡。

5. **进程启动不等于监听**<br>
   Given 只有 `PROCESS_STARTED`，When 查询当前时间轴，Then 不产生蓝色区间，监听 facet 为 `NEVER_OBSERVED`。

6. **授权不等于连接**<br>
   Given `LISTENER_ACCESS=GRANTED` 但没有连接证据，When 查看健康页，Then 权限卡显示已授权，监听卡和主时间轴仍为未确认。

7. **状态通知权限不影响监听区间**<br>
   Given 同一连接有完整正面证据、`POST_NOTIFICATIONS=DENIED`，When 派生模型，Then监听区间仍按证据为蓝色，状态权限卡独立显示不可见警告。

8. **渠道不影响监听区间**<br>
   Given 渠道为 `DISABLED`、监听连接有正面证据，When 派生模型，Then 不把蓝区间改黄，只在渠道 facet 给出设置入口。

9. **状态通知残留不算证据**<br>
   Given 普通状态通知仍在通知栏但新进程没有监听连接事实，When 打开健康页，Then 时间轴保持黄色，状态通知存在不被写入证据。

10. **查询完整覆盖**<br>
    Given 任意合法证据序列和查询范围，When 派生区间，Then 输出无重叠、无空洞，首段从 `rangeStart` 开始、末段在 `rangeEnd` 结束。

11. **同时间稳定顺序**<br>
    Given 连接和断连具有相同 UTC 时间但不同 `evidenceSequence`，When 重复派生，Then 每次按序列得到相同零长度边界处理和后续黄色结果。

12. **时区切换**<br>
    Given 数据库存 UTC，When 设备更换时区或 12/24 小时制，Then 区间事实和排序不变，只重新格式化显示时间。

13. **长待机不补蓝**<br>
    Given 设备息屏 8 小时且没有自然正面证据，When 下次打开应用，Then 未覆盖时段显示黄色，期间 OMN 没有为时间轴产生周期唤醒或写盘。

14. **分页一致性**<br>
    Given 10,000 条历史和同一证据集，When 使用不同通知页大小加载相同 UTC 范围，Then 健康区间边界相同，不因分页边界改变。

## 9. 权限与生命周期边界

- **通知使用权撤销**：观察到 `NOT_GRANTED` 后结束蓝色候选；应用无法观察到的更早撤销时刻不回填。
- **监听断连**：真实断连是明确边界；平台未回调的突然失效只能在下次证据时显现为空档。
- **进程重建**：新会话不能延伸旧会话的实时投影。旧会话最后正面证据后的历史重新按保守规则派生。
- **手机重启**：单调时钟不跨重启使用；重启前后用 UTC 和不同会话 ID，空档默认黄色。
- **正常停止**：`NORMAL_STOP` 结束进程 facet，但如果没有监听断连证据，它本身不新增蓝色监听区间。
- **壁钟跳变**：同会话用 `occurredElapsed` 与稳定序列检测；跨会话不推断连续性，诊断说明时间调整。
- **证据写入失败**：未持久化事实不能用于历史蓝段；当前内存状态可显示为实时状态，并明确“历史证据未保存”。
- **无网络**：派生与显示完全离线；网络不属于五个健康 facet。

## 10. 错误状态

| 错误 | 触发条件 | 用户看到什么 | 系统行为 |
|---|---|---|---|
| `EVIDENCE_QUERY_FAILED` | 健康证据读取失败 | “无法读取运行记录”及重试入口 | 当前范围全部按黄色显示，不伪造蓝色。 |
| `EVIDENCE_PERSIST_FAILED` | 真实事实未能写入 | “部分运行证据未保存” | 当前实时状态可显示，历史不使用该事实。 |
| `INVALID_CONNECTION_REFERENCE` | 连接事件缺 ID 或跨会话复用 | “运行记录存在异常” | 忽略无效蓝色候选，保留去敏诊断枚举。 |
| `NON_MONOTONIC_EVIDENCE` | 同会话 UTC 与单调时间冲突 | 显示时间调整说明 | 按稳定序列派生，不输出倒置区间。 |
| `INVALID_QUERY_RANGE` | `rangeEnd <= rangeStart` | 不渲染轨道并记录开发错误 | 返回类型化错误，不查询数据库。 |
| `CURRENT_STATE_UNAVAILABLE` | 当前内存连接状态不可读 | “当前监听状态未确认” | 不做实时蓝色投影。 |
| `REPAIR_DESTINATION_UNAVAILABLE` | 系统设置入口无法打开 | 手动设置路径说明 | 不崩溃；保留当前 facet。 |

错误发生时默认向保守方向退化为 `UNCONFIRMED`；不允许为保持视觉连续而回用陈旧蓝色缓存。

## 11. 隐私、无障碍与性能约束

- 健康证据只含枚举、会话/连接 ID、UTC/单调时间和稳定序列，不含通知标题、正文、包内动作、URI、内容 ID 或 `PendingIntent`。
- 健康详情中的设备/权限信息只在本地显示；默认无网络、无遥测、无远程心跳。
- 蓝色实线和黄色虚线必须同时配套“已确认运行”“未确认运行”文字与 TalkBack 描述，普通/大号文字和非文本元素满足非功能需求对比度要求。
- 派生算法是纯 Kotlin 函数，不在 Compose 绘制阶段查询数据库或扫描全量历史。
- 只查询当前可见 UTC 范围和边界前置事实；10,000 条通知不得导致加载全部健康历史或全部通知条目。
- 当前时刻只在页面显示、真实生命周期变化或用户刷新时重新投影；不为移动“现在”端点运行后台计时器。
- 不使用轮询、唤醒锁、精确闹钟、高频 WorkManager 或为了蓝条存在的独立前台服务。
- 8 小时息屏无通知场景中，本功能主动唤醒和周期写入必须为零；绝对 CPU/PSS 预算由 A14 在 Phase 0 锁定。

## 12. 测试要求

### 12.1 自动化测试

- 表驱动覆盖每个 `HealthEvidenceKind` 的必填字段和 facet 匹配。
- 纯派生函数覆盖：连续正面证据、明确断连、突然终止、新会话、权限撤销、实时投影和只有进程事实。
- 性质测试验证任意合法输入下区间完整覆盖、无重叠、正长度、确定性和不同连接不混合。
- 同一 UTC 时间按 `evidenceSequence`、同会话壁钟前跳/后跳、跨重启无单调时钟的测试。
- `POST_NOTIFICATIONS`、渠道和状态通知存在不改变主监听区间的独立性测试。
- 查询边界前置事实和不同分页大小输出一致性测试。
- 时区、12/24 小时切换只改变格式化结果。
- Compose 语义树、线型/文字双编码、TalkBack 顺序、48dp、最大字体、深浅色和动态配色测试。

### 12.2 红魔 11 Pro+ 真机测试

- 已知时点执行连接、断连、撤权、恢复、正常关闭、强制终止、进程重建和手机重启，并与派生区间逐段对账。
- 8 小时锁屏无通知，核对黄色比例、额外唤醒、数据库写入和耗电。
- 真实通知到达和活动通知补扫作为正面证据，确认不泄露正文。
- `POST_NOTIFICATIONS` 和状态渠道逐项开关，确认只改变各自 facet。
- 普通状态通知残留与实际进程/监听状态对照，确认不进入蓝色证据。
- 10,000 条历史下首屏、滚动和区间查询不全表载入。
- 全部结论使用 release 构建；模拟器只辅助纯规则测试。

## 13. Phase 0 Spike 与决策门

### 13.1 `SP-07 健康证据与区间精度` 必须回答

1. 红魔 11 Pro+ 上哪些监听生命周期回调稳定可得，断连、系统回收和强制终止分别留下什么证据？
2. `LISTENER_CONNECTED` 到明确断连之间能否按本规格视为确认区间，厂商行为是否存在反例？
3. 活动通知补扫成功可证明到什么程度，是否应作为正面证据？
4. 只用自然事件时蓝/黄区间的实际精度与用户可理解性如何？
5. 是否存在不增加主动唤醒的自然活跃确认；若存在，其触发和证据语义是什么？

### 13.2 证据产物

- 预先标注真实动作时间的会话/连接事实线与派生结果；
- 正常断连、突然终止、长待机、重启和权限切换矩阵；
- 每类证据的可靠性、缺失可能和可支持区间边界；
- 8 小时息屏主动唤醒/写入为零的记录；
- 用户文案与无障碍描述对黄色“不确定”语义的人工核对结果。

### 13.3 决策门

- **GO**：派生规则没有虚假蓝段；五个 facet 独立；黄色含义可理解；时间轴不引入主动周期唤醒；规则可由自动化和真机事实复现。
- **REDIRECT**：某类证据不可靠或蓝段精度低于预期；删除该证据、缩短可确认区间或接受更多黄色，并先更新规格。
- **STOP**：产品只有借助轮询、唤醒锁、精确闹钟或高频后台任务才能增加蓝色覆盖，且用户拒绝通过计划变更接受 Phase 0 实测得到的黄色区间比例。

A11 只有在 Phase 0 锁定正面证据集合、区间算法、可达精度和零额外唤醒结论后，才可在 `v0.3` 标记完成。
