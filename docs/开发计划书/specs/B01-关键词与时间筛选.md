# B01 关键词与时间筛选

状态：`[候选] plan-v1.0`

## 1. 规格元数据

| 项目 | 值 |
|---|---|
| 功能 ID | `B01` |
| 优先级 | `[B]` |
| 主交付版本 | `v0.5` |
| 前置功能 | `A06 稳定排序`、`A07 时间窗应用抽屉`、`A08 本地持久化`、`A12 多应用查看筛选` |
| 被依赖功能 | 无（当前路线图） |
| 相关 Spike | `SP-08（架构 S7）排序、抽屉、筛选与分页`、`SP-09（架构 S8）持久化、隐私与性能基线` |

本功能是收件箱的只读查询条件，不改变监听、监控排除、持久化、动作或通知事实。

## 2. 目标与非目标

### 2.1 目标

- 用户可以按标题、正文或来源应用名称中的本地关键词查找已保存通知。
- 用户可以按 `firstReceivedAt` 的 UTC 瞬时选择闭合时间范围。
- 关键词、时间和 A12 多来源筛选按逻辑 AND 组合，结果保持 A06 基础全序。
- 全部查看条件先作用于条目流，A07 再对当前可见流分组。
- 查询完全本地执行，不记录搜索历史，不改变后台采集。

### 2.2 非目标

- 不搜索尚未持久化、已排除或已经删除的通知。
- 不使用网络、B 站 API、账号或服务端全文检索。
- 不按 `originalPostTime` 或 `lastUpdatedAt` 限定时间。
- 不支持正则表达式、模糊拼音、分词语法、布尔查询语言或跨字段拼接匹配。
- 不把关键词变成监控规则、排除规则或自动清理规则。

## 3. 术语与匹配语义

| 术语 | 精确定义 |
|---|---|
| 原始关键词 | 用户在当前筛选界面输入的 Unicode 文本。 |
| 规范关键词 | 对原始关键词去除首尾 Unicode White_Space、执行 Unicode NFKC，再做 locale-independent Unicode case folding 的结果。 |
| 可搜索字段 | 当前 `NotificationItem` 的 `sourceLabelSnapshot`、`title`、`body`，分别规范化后参与比较。 |
| 子串匹配 | 规范关键词完整连续地出现在任一单独可搜索字段中；不跨字段边界拼接。 |
| `TimeRange` | `startInclusive` 与 `endInclusive` 构成的 UTC 闭区间。 |
| 当前可见流 | 来源、关键词与时间条件都命中的条目按 A06 基础全序形成的流。 |

全局不变量：

1. 关键词为空或规范化后为空等价于没有关键词条件。
2. 时间条件为空等价于没有时间限制。
3. 来源、关键词、时间之间使用 AND；`includedSources` 内部仍使用 OR。
4. 时间判断只使用 `firstReceivedAt`，边界两端都包含。
5. 查询条件不写 `MonitoringPolicy`、`NotificationItem`、`NotificationEvent` 或 `ActionTarget`。
6. 结果始终按 `firstReceivedAt DESC, ingestSequence DESC, itemId DESC`。

## 4. 输入与输出契约

### 4.1 `SearchKeywordInput`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `rawText` | `String` | 是 | 最多 256 个 Unicode code point；只存在当前 UI 状态，不写日志。 |

### 4.2 `SearchKeyword`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `rawText` | `String` | 是 | 用于输入框回显；离开当前筛选会话后清除。 |
| `normalizedText` | `String` | 是 | 去首尾 White_Space → NFKC → locale-independent case folding；非空。 |
| `codePointCount` | `NonNegativeInt` | 是 | 原始输入 code point 数，用于长度验收。 |

若规范化后为空，输出不是空 `SearchKeyword`，而是 `keyword=null`。

### 4.3 `TimeRange`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `startInclusive` | `InstantUtc` | 是 | 必须小于或等于 `endInclusive`。 |
| `endInclusive` | `InstantUtc` | 是 | 必须大于或等于 `startInclusive`。 |

UI 以设备当前时区收集和显示本地日期时间，但提交前必须解析为无歧义 `InstantUtc`。时间范围不得保存为格式化字符串。

#### 4.3.1 `LocalTimeRangeInput`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `startLocal` | `LocalDateTime` | 是 | 用户输入的本地开始日期时间。 |
| `endLocal` | `LocalDateTime` | 是 | 用户输入的本地结束日期时间。 |
| `zoneId` | `ZoneId` | 是 | 提交时设备时区；不能只保存数值偏移。 |
| `startSelectedOffset` | `ZoneOffset?` | 否 | 开始时间落在夏令时重叠区且存在两个有效偏移时必填。 |
| `endSelectedOffset` | `ZoneOffset?` | 否 | 结束时间落在夏令时重叠区且存在两个有效偏移时必填。 |

`ResolveLocalTimeRangeResult`：

| 结果 | 输出字段 | 精确定义 |
|---|---|---|
| `RESOLVED` | `timeRange: TimeRange` | 两端均解析为唯一 UTC 瞬时且开始不晚于结束。 |
| `NONEXISTENT_LOCAL_TIME` | `boundary: START \| END` | 该本地时间在 `zoneId` 下没有有效偏移；不提交查询。 |
| `AMBIGUOUS_LOCAL_TIME` | `boundary: START \| END`、`validOffsets: Set<ZoneOffset>` | 有两个有效偏移但未明确选择；不静默猜测。 |
| `OFFSET_MISMATCH` | `boundary: START \| END` | 提供的偏移不属于该本地时间的有效偏移集合。 |
| `INVALID_TIME_RANGE` | `startInclusive: InstantUtc`、`endInclusive: InstantUtc` | 两端可解析，但开始晚于结束。 |

每个解析结果变体列出的输出字段均为该变体必填；未列出的变体字段不得返回。

### 4.4 `KeywordTimeFilter`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `keyword` | `SearchKeyword?` | 否 | 空表示不按关键词过滤。 |
| `timeRange` | `TimeRange?` | 否 | 空表示不按时间过滤。 |

### 4.5 `ApplyKeywordTimeFilterCommand`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `rawKeyword` | `String?` | 否 | `null` 或空白表示清除关键词；非空按 4.1 校验。 |
| `timeRange` | `TimeRange?` | 否 | 两端同时存在或整体为空。 |

### 4.6 应用结果

| 结果 | 输出字段 | 含义 |
|---|---|---|
| `APPLIED` | `filter: KeywordTimeFilter`、`queryFingerprint: InboxQueryFingerprint` | 条件有效，新查询代从首屏开始。 |
| `NO_CHANGE` | `filter: KeywordTimeFilter`、`queryFingerprint: InboxQueryFingerprint` | 规范化后与当前条件相同；不重启查询。 |
| `INVALID_KEYWORD_LENGTH` | `actualCodePoints: NonNegativeInt`、`max=256` | 不应用；输入框保留并给出明确限制。 |

每个应用结果变体列出的输出字段均为该变体必填；未列出的变体字段不得返回。

`ApplyKeywordTimeFilterCommand.timeRange` 只接收 4.3.1 的 `RESOLVED` 输出；其他本地时间解析结果不会构造该命令。

### 4.7 组合查询

组合查询沿用架构 `InboxFilter`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `includedSources` | `Set<AppUserKey>` | 是 | A12 提供；空为全部，非空为 OR。 |
| `timeRange` | `ClosedRange<InstantUtc>?` | 否 | 使用本规格 `TimeRange` 的闭区间语义；空为不限时间。 |

`InboxQueryCriteria`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `inboxFilter` | `InboxFilter` | 是 | 保留 A12 的 `includedSources`，`timeRange` 使用当前 B01 时间条件。 |
| `keyword` | `SearchKeyword?` | 否 | 使用当前 B01 关键词条件；为空表示不限关键词。 |

查询构建器把 `KeywordTimeFilter.timeRange` 写入 `InboxFilter.timeRange`，把 `KeywordTimeFilter.keyword` 写入 `InboxQueryCriteria.keyword`；每个条件只有一个查询事实来源。

`InboxQueryFingerprint` 使用 A12 的值相等性：只由来源集合、UTC 闭区间和 `normalizedText` 决定，不由 `rawText`、输入时区显示格式或当前 Paging 数据代决定。

查询匹配使用以下 `SearchableNotificationItem`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `itemId` | `ItemId` | 是 | 结果稳定键。 |
| `sourcePackage` | `PackageName` | 是 | 与 `sourceUser` 构成来源键。 |
| `sourceUser` | `AndroidUserRef` | 是 | 不同 Android 用户分开匹配。 |
| `sourceLabelSnapshot` | `String?` | 否 | 可搜索字段。 |
| `title` | `String?` | 否 | 可搜索字段。 |
| `body` | `String?` | 否 | 可搜索字段。 |
| `firstReceivedAt` | `InstantUtc` | 是 | 时间条件与主排序键。 |
| `ingestSequence` | `StableSequence` | 是 | 次排序键。 |
| `actionState` | `ActionStateSummary` | 是 | 只用于结果展示，不参与匹配。 |

`FilteredInboxResult`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `queryFingerprint` | `InboxQueryFingerprint` | 是 | 对应组合条件。 |
| `criteria` | `InboxQueryCriteria` | 是 | 与实际执行条件一致。 |
| `timeline` | `PagedTimelineStream<TimelineNode>` | 是 | 命中条目先按 A06 排序，再由 A07 分组。 |
| `isEmpty` | `Boolean` | 是 | 没有命中条目时为 `true`。 |

`TimelineNode` 为单条节点或同来源抽屉节点；抽屉展开成员仍是各自命中的 `SearchableNotificationItem`。

## 5. 精确查询规则

### 5.1 关键词

对每个条目：

```text
matchesKeyword(item, null) = true

matchesKeyword(item, keyword) =
    normalize(item.sourceLabelSnapshot).contains(keyword.normalizedText)
    OR normalize(item.title).contains(keyword.normalizedText)
    OR normalize(item.body).contains(keyword.normalizedText)
```

- 可空字段为空时视为“不匹配该字段”，不是字符串 `null`。
- 三个字段分别匹配；关键词末尾在标题、开头在正文不算跨字段命中。
- 包名、URI、内容 ID、动作目标、诊断事件和通知 extras 不在搜索范围。
- 内容更新后以当前 `NotificationItem.title/body` 重新判断；可能进入或离开结果，但 `firstReceivedAt` 和相对排序不变。

### 5.2 时间

```text
matchesTime(item, null) = true

matchesTime(item, range) =
    range.startInclusive <= item.firstReceivedAt
    AND item.firstReceivedAt <= range.endInclusive
```

- 恰好等于开始或结束时刻的条目必须命中。
- 时区、locale、12/24 小时制只影响输入解析与显示，不改变存储瞬时或查询结果。
- 对夏令时重叠/缺失的本地时间，UI 必须按 4.3.1 返回明确结果；只有 `RESOLVED` 可以进入 `ApplyKeywordTimeFilterCommand`。

### 5.3 组合

```text
matchesSource(item, includedSources) =
    includedSources.isEmpty()
    OR AppUserKey(item.sourceUser, item.sourcePackage) ∈ includedSources

matches(item) =
    matchesSource(item, inboxFilter.includedSources)
    AND matchesKeyword(item, keyword)
    AND matchesTime(item, inboxFilter.timeRange)
```

所有条件在查询层作用后，再执行 A06 排序和 A07 分组。条件顺序可由查询优化器改变，但逻辑结果必须一致。

## 6. 状态与交互

### 6.1 筛选状态机

```text
ACTIVE(currentFilter)
  → 打开筛选面板 → EDITING(draft)
      ├─ 修改关键词/时间 → VALIDATING
      │                       ├─ 有效 → EDITING(validDraft)
      │                       └─ 无效 → EDITING(error)
      ├─ 取消 → ACTIVE(currentFilter)
      ├─ 清除关键词/时间 → EDITING(null, null)
      └─ 应用有效草稿 → ACTIVE(newFilter) + 新查询代
```

- 关键词输入可使用短防抖只控制前台预览查询；不得建立系统定时任务或后台唤醒。最终“应用”立即规范化并创建新查询代。
- B01 条件是临时查看状态：可在当前进程和配置变化中恢复，但不写长期搜索历史；进程被系统终止后默认清除关键词和时间条件。
- A12 的 `includedSources` 不因清除 B01 条件而改变。
- 活跃条件必须以文本/图标和无障碍描述显示，不能只改变结果数量。

### 6.2 交互要求

- 使用 Material 3 搜索输入和时间范围控件；所有点击目标至少 48dp。
- 输入错误紧邻对应字段显示，TalkBack 能朗读原因和允许范围。
- “清除关键词与时间”只清除 B01 条件；另有明确入口清除 A12 来源筛选。
- `EMPTY_RESULT` 显示“当前筛选没有记录”，并提供清除 B01 条件的操作；不得暗示监听停止。
- 最大字体、横竖屏、分屏、edge-to-edge 和输入法场景下仍可完成输入、时间选择、应用和清除。

## 7. 用户故事

- 作为用户，我要输入 UP 主名或通知标题的一部分，找到对应的已保存通知。
- 作为用户，我要限定某一天或一段时间，避免翻阅全部历史。
- 作为用户，我要把关键词/时间与 B 站、短信等多来源选择组合。
- 作为用户，我要确信搜索只改变眼前列表，不会让其他应用停止记录。

## 8. Given / When / Then 验收

### AC-B01-01 空白关键词等价于无条件

- Given 收件箱有固定条目集合
- When 分别应用 `null`、空字符串和仅 Unicode 空白的关键词
- Then 三次结果与无关键词条件完全相同
- And 不产生搜索历史写入

### AC-B01-02 NFKC 与大小写折叠

- Given 标题规范化后包含 `abc123`
- When 用户输入规范化后同为 `abc123` 的全角或不同大小写文本
- Then 该条目命中
- And 使用设备土耳其语或其他 locale 不改变结果

### AC-B01-03 单字段连续子串

- Given A 的标题为“新的投稿通知”，B 的来源名为“哔哩哔哩”，C 的标题末尾为“新的”且正文开头为“投稿通知”
- When 搜索“投稿”
- Then A 命中
- When 搜索“哔哩”
- Then B 命中
- When 搜索“新的投稿”
- Then C 不因跨标题与正文拼接而命中

### AC-B01-04 空字段安全

- Given 一个条目的标题和正文为空，来源名为“系统界面”
- When 搜索“系统”
- Then 该条目命中
- When 搜索“通知”
- Then 该条目不命中且查询不崩溃

### AC-B01-05 时间闭区间

- Given 条目分别位于开始时刻、区间中间、结束时刻和结束后最小可表示单位
- When 应用该时间范围
- Then 前三条命中
- And 第四条不命中

### AC-B01-06 无效范围不应用

- Given 当前结果使用有效条件 F
- When 用户提交 `startInclusive > endInclusive`
- Then 返回 `INVALID_TIME_RANGE`
- And 条件 F 与当前结果保持不变

### AC-B01-07 与多来源筛选取 AND

- Given 关键词和时间命中 A1、B1、C1，A12 选择 `{A,B}`
- When 执行组合查询
- Then 结果只含 A1、B1
- And 仍按 A06 基础全序

### AC-B01-08 不改变采集

- Given 当前关键词和时间条件使 B 的记录不可见，B 未被 A02 排除
- When B 新通知到达
- Then B 仍进入采集与持久化
- And `MonitoringPolicy.revision` 不变
- When 清除 B01 条件
- Then B 的新记录在正确位置出现

### AC-B01-09 更新改变命中但不顶置

- Given 旧条目 A 当前不匹配关键词，较新条目 B 匹配
- When A 正文更新后开始匹配
- Then A 进入结果
- And B 仍因 `firstReceivedAt` 较新而排在 A 前

### AC-B01-10 筛选先于抽屉

- Given 全部流 `A10:42, B10:40, A10:35`，关键词只命中两条 A
- When 查询并分组
- Then 当前可见流只有两条 A，并可形成 A 抽屉
- And B 不计入跨越数
- And B 的通知事实不变

### AC-B01-11 时区变化不改结果

- Given 已应用 UTC 闭区间并记录命中 `itemId` 序列
- When 改变设备时区和 12/24 小时制
- Then UI 按新区域格式显示时间
- And 同一 UTC 区间的命中与顺序不变

### AC-B01-12 长度边界

- Given 原始关键词恰好 256 个 Unicode code point
- When 应用
- Then 可以进入规范化和查询
- Given 原始关键词为 257 个 code point
- When 应用
- Then 返回 `INVALID_KEYWORD_LENGTH` 且旧条件不变

### AC-B01-13 分页一致

- Given 10,000 条固定历史与固定组合条件
- When 分别以多种页大小读完全部结果
- Then 命中 `itemId` 序列完全相同
- And 无重复、遗漏、改序或因页边界改变的抽屉成员

### AC-B01-14 夏令时缺失与重叠不静默猜测

- Given `zoneId` 的规则使开始本地时间没有有效偏移
- When 解析 `LocalTimeRangeInput`
- Then 返回 `NONEXISTENT_LOCAL_TIME(boundary=START)` 且不创建查询代
- Given `zoneId` 的规则使结束本地时间有两个有效偏移且用户尚未选择
- When 解析同一输入
- Then 返回 `AMBIGUOUS_LOCAL_TIME(boundary=END, validOffsets=...)` 且不创建查询代
- When 用户选择其中一个有效偏移并重新解析
- Then 该边界使用所选偏移生成唯一 `InstantUtc`

## 9. 边界条件与错误状态

| 场景/错误码 | 用户可见状态 | 系统行为 |
|---|---|---|
| `INVALID_KEYWORD_LENGTH` | 显示当前 code point 数与最大 256 | 不截断、不应用、不记录输入。 |
| `INVALID_TIME_RANGE` | 标记开始/结束关系错误 | 保持最后成功条件。 |
| `NONEXISTENT_LOCAL_TIME` | 标出不存在的开始或结束本地时间 | 用户修改为该时区中的有效本地时间前不查询。 |
| `AMBIGUOUS_LOCAL_TIME` | 显示两个有效偏移供用户选择 | 用户选择明确偏移前不查询。 |
| `OFFSET_MISMATCH` | 说明所选偏移已不适用于当前时区规则 | 清除无效偏移并重新解析；不沿用旧偏移猜测瞬时。 |
| `QUERY_FAILED` | 保留最后成功页面并显示“重试”操作 | 只在用户点击后重新发起一次查询；不得自动循环或全表载入兜底。 |
| 规范化后为空 | 视为 `keyword=null` | 不报错，不建立空字符串扫描。 |
| 可搜索字段缺失 | 该字段不匹配 | 继续检查其他字段，不崩溃。 |
| 来源标签变化 | 使用当前条目保存的 `sourceLabelSnapshot` | 不改变来源身份或排序。 |
| 内容更新时查询失效 | 重新建立查询代 | 不混用旧页；不改变排序键。 |
| 结果为空 | 显示当前筛选无记录 | 不自动清除条件，不解释为采集失败。 |

## 10. 数据流

```text
用户输入关键词/时间
  → 规范化与校验
  → KeywordTimeFilter（临时查看状态）
  + InboxFilter.includedSources（A12）
  → InboxQueryCriteria
  → Room / Paging 查询：来源 AND 关键词 AND firstReceivedAt 范围
  → A06 三键稳定排序
  → A07 对当前可见流分组
  → Compose UI
```

该流程没有到 `MonitoringPolicyRepository`、`NotificationListenerAdapter` 或摄取写端口的路径。

## 11. 隐私与性能要求

- 原始和规范关键词不写日志、诊断事件、遥测或长期搜索历史；进程结束后清除 B01 条件。
- 查询、规范化和索引完全位于应用私有空间，并从 Android 自动云备份与跨设备迁移中排除。
- 可搜索字段不包含完整 URI、内容 ID、动作令牌、`PendingIntent`、验证码分类或通知 extras。
- 若为搜索增加派生索引，字段范围、存储增量、更新事务一致性和清理行为必须由 `SP-09` 证明；不得无界复制正文。
- 查询在 Room/Paging 层执行，不把 10,000 条历史载入 UI 后过滤；关键词防抖只在前台当前会话运行。
- 无筛选操作时不产生数据库写入、周期查询、网络、唤醒或后台任务。
- 10,000 条场景记录首屏、输入后查询、时间筛选、组合筛选、翻页、抽屉和 PSS；绝对预算由 Phase 0 锁定。
- 同场景首屏、筛选、分组耗时或后台内存无解释回退超过 10% 时不得通过。

## 12. 测试要求

### 12.1 自动化测试

- 规范化固定夹具：空白、全角/半角、大小写、组合字符、emoji、中文、locale 变化和 256/257 code point。
- 匹配测试：三个可搜索字段分别命中、空字段、不跨字段、包名/URI/动作不参与。
- 时间测试：闭区间两端、单一瞬时、无效范围、时区、夏令时重叠/缺失和 12/24 小时制。
- 组合查询测试：A12 单选/多选/全部与关键词/时间的 AND 结果及 A06 顺序。
- 更新测试：正文更新使条目进入/离开结果但不改变排序键。
- 分页与分组测试：不同页大小得到相同命中序列和 A07 成员。
- 架构边界测试：B01 用例没有监控策略写端口，应用条件不改变 `MonitoringPolicy.revision`。
- Compose 测试：有效/无效输入、清除、取消、空结果、48dp、TalkBack、最大字体、横竖屏和输入法 inset。

### 12.2 真机测试

- 红魔 11 Pro+、release 构建使用 10,000 条去隐私化历史执行关键词、时间和多来源组合筛选。
- 切换系统时区、locale 和 12/24 小时制，核对 UTC 范围结果与顺序。
- 筛选隐藏 B 时触发 B 通知，确认后台仍采集，清除条件后可见。
- 记录查询范围、已加载数、首屏/筛选/翻页/分组耗时、PSS 和数据库增量；报告不含关键词原文或真实通知内容。

## 13. Spike 决策门

- `SP-08` 必须证明：来源、关键词、时间组合后分页不重复/漏项/改序，筛选后的抽屉成员可预测，10,000 条不全量载入。
- `SP-09` 必须锁定：搜索实现的私有存储边界、派生索引增量、内容更新事务一致性、敏感字段扫描及查询绝对预算。
- 若既定匹配语义无法在资源预算内实现，应保留 A12 来源筛选并通过计划变更重新决定 B01 范围；不得暗中把子串搜索改成不同的分词语义。
