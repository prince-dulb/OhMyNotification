# A07 时间窗应用抽屉

状态：`[候选] plan-v1.0`

| 项目 | 值 |

## 2. 目标与非目标

### 2.1 目标

- 在不篡改通知时间事实的前提下，把短时间内同一来源的多条通知压缩成可展开抽屉。
- 允许同一来源通知跨越最多 3 条当前可见的其他来源条目，减少短时推送刷屏。
- 超过 15 分钟或跨越第 4 条其他来源时恢复严格基础时间列表。
- 使用锚点式、非重叠、确定性算法；同一输入不因分页大小、进程重建或重复查询改变组成员。
- 抽屉头明确显示来源、数量和覆盖时间，展开后保留逐条时间、正文、动作状态和点击目标。

### 2.2 非目标

- 不修改 `NotificationItem`、排序键或动作目标。
- 不把抽屉、展开状态或成员关系写成长期通知事实。
- 不把同一包名的不同 Android 用户合并。
- 不按标题、正文、通知渠道或 UP 主建立组。
- 不为了分组一次性载入全部历史。

## 3. 术语与固定参数

| 术语 | 精确定义 |
|---|---|
| 基础全序 | A06 输出的 `firstReceivedAt DESC, ingestSequence DESC, itemId DESC` 条目流。 |
| 当前可见流 | A12/B01 的查看条件先作用后得到的基础全序；被查看筛选隐藏的条目不在流中。 |
| `groupingKey` | `AppUserKey(sourceUser, sourcePackage)`；字段完全相同才算同一来源。 |
| 锚点 | 当前可见流中第一条尚未消费的记录。 |
| 候选成员 | 锚点及向旧方向扫描时满足窗口和跨越条件的同 `groupingKey` 条目。 |
| 跨越条目 | 扫描中遇到且 `groupingKey` 与锚点不同的当前可见条目；即使该条目已属于更早输出的抽屉，仍逐条计数。 |
| 消费 | 某条目已作为 `SingleItemNode` 或某个 `AppDrawerNode` 成员输出，不得再次成为节点或成员。 |

固定首版参数：

| 参数 | 类型 | 值 | 精确定义 |
|---|---|---:|---|
| `window` | `Duration` | 15 分钟 | 锚点与候选最旧成员的 `firstReceivedAt` 差值必须小于或等于 15 分钟。 |
| `maxInterveningOtherItems` | `NonNegativeInt` | 3 | 最多跨过 3 条其他来源记录；即将遇到第 4 条时停止扫描。 |
| `minimumGroupSize` | `PositiveInt` | 2 | 候选成员至少 2 条才输出抽屉。 |
| `strategyVersion` | `GroupingStrategyVersion` | `ANCHOR_V1` | 参数或算法变化必须使用新版本并同步计划与测试。 |

## 4. 输入与输出契约

本规格定义逻辑流；物理分页、查询和缓存方案由架构与 Phase 0 基准锁定。

| `ingestSequence` | `StableSequence` | 是 | 基础全序次键。 |

### 4.4 `AppDrawerNode`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `groupId` | `TimelineGroupId` | 是 | 逻辑相等性由 `strategyVersion + queryFingerprint + groupingKey + 完整有序 memberIds` 决定；可在扫描时增量计算，不使用正文。 |

| `oldestAt` | `InstantUtc` | 是 | 最后一成员的 `firstReceivedAt`。 |
| `count` | `PositiveInt` | 是 | 必须等于完整逻辑 `memberIds` 的元素数，不等于当前已加载数。 |
| `latestSummary` | `NotificationItemSummary` | 是 | 第一成员的来源、标题与动作摘要。 |
| `strategyVersion` | `GroupingStrategyVersion` | 是 | 首版为 `ANCHOR_V1`。 |

`TimelineGroupingResult`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `queryFingerprint` | `InboxQueryFingerprint` | 是 | 必须与输入一致。 |
| `generationId` | `PagingGenerationId` | 是 | 必须与输入一致；不得混合两代节点。 |
| `strategyVersion` | `GroupingStrategyVersion` | 是 | 首版为 `ANCHOR_V1`。 |
| `nodes` | `PagedTimelineStream<TimelineNode>` | 是 | 保持逻辑节点顺序，不含重复成员。 |
| `isEmpty` | `Boolean` | 是 | 仅当当前可见流没有输入条目时为 `true`。 |

### 4.5 UI 展开状态

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `expandedGroupIds` | `Set<TimelineGroupId>` | 是 | 仅属当前 UI 状态；初始为空。 |

展开状态不写入 `NotificationItem` 或抽屉事实表。进程重建后允许恢复仍存在的 `groupId`，不存在的 ID 必须丢弃。

## 5. 锚点式非重叠算法

对一个确定的当前可见流执行：

1. 建立空的 `consumed` 集合，从新到旧找到第一条未消费记录作为锚点。
2. 以锚点建立候选成员列表，`interveningOtherItems=0`。
3. 从锚点下一条向旧方向扫描：
   - 若 `anchor.firstReceivedAt - item.firstReceivedAt > 15 分钟`，停止；
   - 若 `item.groupingKey != anchor.groupingKey` 且 `interveningOtherItems == 3`，在计入该第 4 条之前停止；
   - 若 `item.groupingKey != anchor.groupingKey` 且尚未达到上限，将该条目计入跨越数并继续；该规则不因该条目已被消费而改变；
   - 若 `item.groupingKey == anchor.groupingKey` 且未消费，加入候选成员；
   - 若 `item.groupingKey == anchor.groupingKey` 且已消费，跳过且不再次成组。
4. 候选成员数至少为 2 时：只消费这些同来源成员，在锚点位置输出一个 `AppDrawerNode`；被跨过的其他来源条目不消费。
5. 候选成员不足 2 时：只消费锚点，输出 `SingleItemNode`。
6. 重复步骤 1—5，直到当前可见流结束。
7. 一个 `itemId` 必须且只能出现在一个输出节点中；非重叠是阻断性不变量。

边界为闭区间：恰好相差 15 分钟可以成组；恰好跨 3 条可以成组。第 4 条不同来源或大于 15 分钟都会停止当前锚点扫描。

抽屉输出位置由最新成员即锚点决定。被跨过的其他来源节点随后按自己的基础全序位置输出，因此抽屉头的 `newestAt—oldestAt` 必须明确展示局部跨越。

## 6. 筛选与分页规则

1. A12/B01 先生成当前可见流，A07 再分组。隐藏来源不计入跨越条数。
2. 查看条件变化可以改变抽屉成员，但不得修改任何 `NotificationItem`、`MonitoringPolicy` 或动作目标。
3. 页尾锚点在以下任一条件可证明前不得定组：到达数据末尾、下一条超出 15 分钟、即将遇到第 4 条其他来源，或已取得所有仍可能成为成员的条目。
4. 查询层必须提供有限前瞻或等价 continuation，使相同完整输入在不同页大小下得到相同 `TimelineNode` 与 `memberIds`。
5. 15 分钟内单应用极端突发可对抽屉成员列表单独分页，但逻辑 `count`、最早/最晚时间和成员集合不得因只加载部分成员而改变。
6. 新条目、删除或影响查询命中的内容更新使当前 `generationId` 失效；查看条件变化同时产生新的 `queryFingerprint` 与 `generationId`。两种情况都不得把旧分组 continuation 拼到新流。

## 7. 用户故事与交互

### 7.1 用户故事

- 作为用户，我要把 B 站短时间连续推送收进一个小抽屉，避免时间轴被同一应用占满。
- 作为用户，我要看见抽屉覆盖的起止时间，知道它跨过了哪些时间段。
- 作为用户，我要展开后逐条核对原始时间并点击各自目标。
- 作为用户，我要长时间分隔的同应用通知恢复严格时间排列，避免旧推送被误藏在新抽屉里。

### 7.2 抽屉交互状态

| 状态 | 头部内容 | 用户操作 |
|---|---|---|
| `COLLAPSED` | 应用图标/名称、数量、`oldestAt—newestAt`、最新摘要、展开状态 | 点击 48dp 以上头部展开。 |
| `EXPANDING` | 与折叠态一致 | 短动效仅解释尺寸变化；减少动态效果开启时直接切换。 |
| `EXPANDED` | 同一头部及逐条成员 | 成员按基础全序；每条保留时间、正文、动作状态与点击目标。 |
| `COLLAPSING` | 与展开态一致 | 收起后焦点回到同一抽屉头。 |
| `MEMBER_LOAD_ERROR` | 头部与已加载成员 | 显示成员加载失败及重试，不把抽屉改成不完整的若干单条。 |

- TalkBack 描述至少包含来源、通知数量、起止时间和展开/折叠状态。
- 展开后的成员各自保留独立可访问节点；时间轴视觉层不得吞掉成员焦点。
- 大窗口列表—详情布局中，选中成员的详情不改变组成员或展开状态。

## 8. Given / When / Then 验收

### AC-A07-01 同来源连续通知成组

- Given 基础流为 `A10:42, A10:41, A10:40`
- When 使用 `ANCHOR_V1`
- Then 输出一个 A 抽屉
- And 成员顺序为 10:42、10:41、10:40，数量为 3，范围为 10:40—10:42

### AC-A07-02 短跨度跨一条

- Given 基础流为 `A10:42, B10:40, A10:35`
- When 分组
- Then 输出顺序为 `A抽屉(10:35—10:42), B10:40`
- And A 抽屉恰有两条，B 不被消费

### AC-A07-03 第四条其他来源阻断

- Given 基础流为 `A10:42, B10:40, C10:39, D10:38, E10:37, A10:35`
- When 分组
- Then 两条 A 不组成同一抽屉
- And 基础条目均按各自顺序输出或参与后续独立分组

### AC-A07-04 超过时间窗阻断

- Given 基础流为 `A10:42, B10:40, A10:20`
- When 分组
- Then 两条 A 都保持单条
- And B 保持基础位置

### AC-A07-05 闭区间边界

- Given 两条 A 恰好相差 15 分钟且中间恰有 3 条其他来源
- When 分组
- Then 两条 A 可以组成抽屉
- Given 时间差增加最小可表示单位或增加第 4 条其他来源
- When 再次分组
- Then 两条 A 不组成同一抽屉

### AC-A07-06 Android 用户隔离

- Given 两条通知包名相同但 `sourceUser` 不同
- When 分组
- Then 两条通知不得进入同一抽屉

### AC-A07-07 非重叠

- Given 任意固定输入流
- When 完成分组
- Then 每个输入 `itemId` 在所有节点和成员中出现且只出现一次
- And 不存在成员同时属于两个抽屉

### AC-A07-08 分页不改变成员

- Given 包含页边界候选组的 1,000 条固定数据
- When 分别用页大小 10、37、100 生成完整时间轴
- Then 节点类型、顺序、每个 `groupId` 的有序 `memberIds`、数量和时间范围完全相同

### AC-A07-09 查看筛选先于分组

- Given 全部流为 `A10:42, B10:40, A10:35`，查看筛选隐藏 B
- When 生成当前可见流并分组
- Then A 抽屉仍包含两条 A
- And B 不计入跨越数且不出现在输出
- And `MonitoringPolicy` 与通知事实不变

### AC-A07-10 展开保持逐条事实

- Given 一个折叠抽屉含 3 条不同动作状态的通知
- When 用户展开
- Then 3 条按 A06 基础全序显示各自时间、正文与动作状态
- And 点击任一成员只执行该 `itemId` 的动作

### AC-A07-11 内容更新不改变组

- Given 已形成抽屉且某成员更新标题
- When `firstReceivedAt`、`ingestSequence`、`itemId` 和来源键均不变
- Then 成员集合、顺序和 `groupId` 不变
- And 只更新相应摘要内容

### AC-A07-12 极端单应用突发

- Given 15 分钟内存在超过一个 UI 页容量的同来源通知
- When 折叠和展开抽屉
- Then 头部数量、起止时间和完整逻辑成员集合正确
- And 成员可分页加载，不全量载入全部历史

### AC-A07-13 已消费的其他来源仍计入跨越

- Given 基础流为 `A10:42, B10:41, A10:40, C10:39, D10:38, E10:37, B10:36`
- When A10:42 与 A10:40 先组成抽屉，随后以 B10:41 为锚点继续分组
- Then 已属于 A 抽屉的 A10:40 仍是 B 锚点扫描中的第 1 条跨越条目
- And C、D 分别是第 2、3 条，遇到 E 作为第 4 条时停止
- And B10:41 与 B10:36 不组成同一抽屉

## 9. 边界条件与错误状态

| 场景/错误码 | 用户可见状态 | 系统行为 |
|---|---|---|
| `UNSORTED_INPUT` | 时间轴暂时不可用并提供重试 | 记录不含正文的契约错误；不得在 UI 临时全量排序掩盖上游问题。 |
| `DUPLICATE_ITEM_ID` | 显示数据完整性错误 | 停止受影响分组，不重复或静默丢弃成员。 |
| `QUERY_FINGERPRINT_MISMATCH` | 重新加载当前筛选首屏 | 丢弃旧 continuation 与展开 ID。 |
| `PAGING_GENERATION_MISMATCH` | 重新加载当前数据代首屏 | 丢弃旧 continuation，不把两代节点拼接。 |
| `STRATEGY_VERSION_MISMATCH` | 重新计算当前时间轴 | 不混用两种参数生成同一组。 |
| `MEMBER_LOAD_FAILED` | 抽屉头保留并显示成员加载失败与“重试”操作 | 只在用户点击后重新发起一次成员查询；不得自动循环或改写为错误成员集合。 |
| 来源标签/图标缺失 | 以包名和系统占位图标显示 | 来源键仍用包名与用户，不影响成员。 |
| 标题/正文为空 | 摘要显示明确占位 | 不影响组判定。 |
| 设备时区变化 | 重新格式化头部时间 | 使用 UTC 计算 15 分钟，成员不变。 |
| 抽屉成员动作失效 | 对该成员显示动作错误 | 不解散抽屉，不影响其他成员。 |

## 10. 隐私与性能要求

- 分组只读取来源键、排序键、条目 ID 和最小摘要，不读取完整 URI、`PendingIntent` 或诊断正文。
- `groupId` 不得包含标题、正文、URI 或可逆内容指纹。
- 抽屉是本地派生数据，不联网、不遥测、不写入长期通知表。
- 使用分页、有限前瞻和增量重组；单条内容更新不得重算整个 10,000 条时间轴。
- 10,000 条数据必须覆盖密集、交错、同时间、页边界和极端单应用突发；不全表载入，后台内存不随总历史线性增长。
- 抽屉成员过多时允许成员独立分页，但任何性能策略都不能改变组成员、数量或逐条顺序。
- 展开/收起不产生数据库写入、网络、唤醒或状态通知刷新。
- Phase 0 锁定首屏、翻页、分组、展开、滚动与 PSS 预算；无解释回退超过 10% 时不得通过。

## 11. 测试要求

### 11.1 自动化测试

- 表驱动测试：连续同源、短跨度 `A→B→A`、跨 3/4 条、14:59/15:00/15:01 边界。
- 性质测试：确定性、成员完备、成员唯一、非重叠、成员同来源、组内基础全序。
- 分页测试：不同页大小、锚点落页尾、候选落下一页、数据末尾和失效 continuation。
- 筛选测试：全部、单选、多选、关键词、时间范围切换后按当前可见流重新分组，且不写 `MonitoringPolicy`。
- 时区测试：UTC 瞬时不变时切换 locale、时区和 12/24 小时制，成员不变。
- Compose 测试：折叠/展开、焦点恢复、48dp、TalkBack 描述、最大字体、深浅色和减少动态效果。

### 11.2 真机测试

- 红魔 11 Pro+、release 构建用多应用交错通知核对 15 分钟和跨越 3 条规则。
- 使用 10,000 条生成数据测试冷启动、快速滚动、反复展开、查看筛选和进程重建。
- 对相同数据使用至少三种页大小，导出脱敏节点与成员 ID 序列进行一致性比较。
- 记录已加载条目数、查询范围、首屏/分组/展开耗时、后台与峰值 PSS；真实通知正文不得进入报告。

## 12. Spike 决策门

- `SP-08` 必须证明：锚点式非重叠算法在短/长跨度、跨 3/4 条、筛选和页边界下可预测；不同页大小产生完全相同的成员与顺序；10,000 条不全量载入。
- 若筛选后的跨越计数无法达到确定性，必须保留基础严格时间列表并通过计划变更调整功能；不得用“多数情况下相同”作为通过。
