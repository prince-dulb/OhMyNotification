# A09 原内容跳转规格说明

- **主交付版本**：`v0.1`
- **优先级**：`[A]`
- **规格状态**：`[已确认] plan-v1.0 基线；Phase 0 未决项保持待验证`
- **Phase 0 依赖**：`SP-02 原始动作寿命与持有成本`、`SP-03 B 站持久精确目标`、`SP-09 持久化、隐私与性能基线`
- **功能依赖**：A03 通知事件采集、A04 条目归一化、A08 本地持久化
- **被依赖**：A13 B 站端到端真机验收、A14 性能基线与回归门槛

## 1. 目标与范围

本功能让用户从 OMN 的归档条目回到该通知原本指向的内容，并把三种能力严格分层：

1. 当前 OMN 进程内的原始 `PendingIntent`；
2. 可跨 OMN 进程重建和设备重启保存的精确持久目标；
3. 仅打开来源应用的 `APP_LAUNCH` 降级。

`[已确认]` 前两层才属于精确跳转候选；`APP_LAUNCH` 只表示打开来源应用入口，不得显示为“已回到原内容”。`PendingIntent.send()` 或受控 `Intent` 被系统接受，只证明派发成功，不证明实际落页正确。A13 必须用真实落页另行验证投稿、动态和开播。

`[已确认]` 默认收件箱只显示当前至少有一个精确候选的条目，并使用“尝试打开原内容”而非成功承诺。没有候选、当前进程未恢复运行时动作、运行时动作已明确取消或系统明确拒绝派发的条目进入设置页可访问的“当前无跳转动作归档”；归档状态按当前能力派生，不删除长期条目、不写 Room。归档条目允许用户主动选择“尝试重新获取并打开（不一定成功）”：仅在本次点击中扫描系统当前活动通知、走既有身份与生命周期归并，若为该条目重新取得动作则立即派发。若后续补扫重新取得动作，条目自动回到默认收件箱。

`[已确认]` OMN 不设置基于记录年龄的跳转 TTL。条目创建时间、句柄捕获时间、最后尝试时间和等待天数都不参与“是否过期”的判定。

### 1.1 本功能不做

- 不把 `PendingIntent`、原始 `Intent`、`Parcel` 字节或 Binder 令牌写入 Room、文件、日志或诊断导出。
- 不把通知标题或正文拼成搜索词后称为精确目标。
- 不调用 B 站账号、私有 API、网页抓取或 OMN 网络请求来补全目标。
- 不在后台周期探测目标是否仍可打开。
- 不为归档尝试启动轮询、持续重绑或重复后台重扫；每次重扫只能由用户明确点击触发，并有有限等待时间。
- 不因句柄年龄、条目年龄或长期未点击而主动标记失效或删除动作。
- 不在精确策略失败后自动打开来源应用；必须由用户在当前失败界面明确选择降级。
- 不承诺其他应用创建的 `PendingIntent` 永久有效，也不承诺来源内容永久存在。

## 2. 术语与分层契约

| 术语 | 精确定义 |
|---|---|
| `RUNTIME_PENDING_INTENT` | 从原通知取得、仅注册在当前 `runtimeSessionId` 内存中的原始动作句柄；进程重建后不可恢复。 |
| `PERSISTENT_EXACT_TARGET` | 经来源提取器验证结构与来源的 URI，或“内容类型 + 内容 ID”结构化目标；可持久保存，但实际页面仍可能删除或路由变化。 |
| `APP_LAUNCH` | 由来源包名解析出的应用入口；只打开来源应用，不保证任何具体内容。 |
| 精确派发 | 系统接受运行时动作或精确持久目标的启动请求。它不是实际落页证明。 |
| 精确落页 | 真机上实际显示的内容身份与通知预期身份一致；首页、搜索页、推荐页或错误页均不算。 |
| 当前进程 | 由一个 `runtimeSessionId` 标识的 OMN 进程会话；进程重建必须生成新 ID。 |
| 人为 TTL | 仅因记录或动作达到某个年龄便被 OMN 判失效的规则；本项目不允许此规则。 |

## 3. 用户故事

- 作为误划掉系统通知的用户，我点击 OMN 中的记录后，希望优先执行最接近原通知的动作。
- 作为隔天或重启后再看的用户，我希望 OMN 不因记录变旧而拒绝尝试仍受支持的持久目标。
- 作为面对失效目标的用户，我希望看到具体失败原因，并自行决定是否只打开来源应用。
- 作为重视真实性的用户，我不希望“打开了 B 站首页”被计为“已打开原视频、动态或直播间”。

## 4. 输入契约

以下是领域输入，不是 Room entity、表结构或迁移方案。

### 4.1 `JumpRequest`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `itemId` | `ItemId` | 是 | 必须指向当前可查询的长期通知条目。 |
| `requestedAt` | `InstantUtc` | 是 | 用户操作的 UTC 时刻；只用于尝试记录，不用于 TTL。 |
| `runtimeSessionId` | `RuntimeSessionId` | 是 | 必须等于当前进程会话；不能从持久层恢复旧值。 |
| `intent` | `JumpUserIntent` | 是 | `OPEN_EXACT` 或 `OPEN_APP_FALLBACK`。 |
| `fallbackConsent` | `FallbackConsent` | 是 | `NOT_GRANTED` 或 `GRANTED_IN_CURRENT_FAILURE_FLOW`；只有用户点击明确降级按钮后才能为后者。 |

规则：

1. 条目首次点击固定产生 `OPEN_EXACT + NOT_GRANTED`。
2. `OPEN_APP_FALLBACK` 必须同时带 `GRANTED_IN_CURRENT_FAILURE_FLOW`，且该确认只适用于当前条目、当前一次交互；不得保存为全局偏好。
3. 重复点击是新的请求；不得复用上次的“已同意降级”。

### 4.2 `RuntimeActionCandidate`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `itemId` | `ItemId` | 是 | 与已提交条目一致。 |
| `runtimeSessionId` | `RuntimeSessionId` | 是 | 只对同一当前会话有效。 |
| `pendingIntent` | `PendingIntent` | 是 | 仅存在进程内存；不得通过本契约之外的端口输出。 |
| `role` | `RuntimeActionRole` | 是 | v0 精确内容动作使用 `CONTENT`。 |
| `capturedAt` | `InstantUtc` | 是 | 仅诊断捕获时刻，不构成 TTL。 |
| `attemptState` | `RuntimeAttemptState` | 是 | `UNTRIED`、`DISPATCH_ACCEPTED`、`CANCELED`、`CONSUMED` 或 `SECURITY_REJECTED`。 |

### 4.3 `PersistentExactTarget`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `targetId` | `TargetId` | 是 | 条目内不变的内部标识。 |
| `itemId` | `ItemId` | 是 | 所属条目。 |
| `kind` | `ExactTargetKind` | 是 | `EXACT_URI` 或 `SOURCE_CONTENT_ID`；不得为 `APP_LAUNCH`。 |
| `provider` | `ProviderId` | 是 | 标识经验证的通用或来源专用解析器版本。 |
| `payload` | `ValidatedTargetPayload` | 是 | 规范化 URI，或内容类型与 ID；不得是任意序列化 `Intent`。 |
| `priority` | `Int` | 是 | 同一条目内唯一，数值越小越先尝试。 |
| `validationState` | `TargetValidationState` | 是 | `UNTESTED`、`USABLE`、`TEMPORARY_FAILURE` 或 `PERMANENT_FAILURE`。 |
| `lastAttemptAt` | `InstantUtc?` | 否 | 只有用户实际尝试后更新；不参与年龄淘汰。 |
| `lastFailureReason` | `ActionFailureReason?` | 否 | 只存枚举，不保存完整 URI、查询参数或异常消息中的敏感内容。 |

### 4.4 `AppLaunchCandidate`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `sourcePackage` | `PackageName` | 是 | 必须来自条目来源，不接受界面传入任意包名。 |
| `sourceUser` | `AndroidUserRef` | 是 | 与通知来源用户一致。 |
| `isResolvable` | `Boolean` | 是 | 在用户确认降级后即时检查。 |

## 5. 输出契约

### 5.1 `JumpResult`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `itemId` | `ItemId` | 是 | 与请求一致。 |
| `completedAt` | `InstantUtc` | 是 | 本次解析完成时刻。 |
| `outcome` | `JumpOutcome` | 是 | 见 5.2。 |
| `selectedLayer` | `JumpLayer?` | 否 | `RUNTIME_PENDING_INTENT`、`PERSISTENT_EXACT_TARGET`、`APP_LAUNCH`；没有派发时为空。 |
| `attemptedTargetIds` | `List<TargetId>` | 是 | 仅内部 ID，按实际尝试顺序；不得包含 payload。 |
| `failureReason` | `ActionFailureReason?` | 否 | 精确失败或降级失败时必填。 |
| `fallbackAvailable` | `Boolean` | 是 | 仅表示来源应用入口当前可解析，不表示已获用户同意。 |
| `landingVerification` | `LandingVerification` | 是 | `NOT_OBSERVED`、`EXPECTED_TARGET_VERIFIED`、`WRONG_TARGET_VERIFIED` 或 `ERROR_PAGE_VERIFIED`。生产派发默认 `NOT_OBSERVED`；A13 真机验收填写实际结果。 |

### 5.2 `JumpOutcome`

| 值 | 含义 | 是否可计为精确落页通过 |
|---|---|---:|
| `EXACT_DISPATCH_ACCEPTED_RUNTIME` | 系统接受当前进程原始动作。 | 否；还需 `EXPECTED_TARGET_VERIFIED`。 |
| `EXACT_DISPATCH_ACCEPTED_PERSISTENT` | 系统接受精确持久目标。 | 否；还需 `EXPECTED_TARGET_VERIFIED`。 |
| `APP_LAUNCH_DISPATCH_ACCEPTED` | 系统接受来源应用入口。 | 否。 |
| `EXACT_UNAVAILABLE` | 两层精确策略均不存在或均失败，尚未执行降级。 | 否。 |
| `APP_LAUNCH_UNAVAILABLE` | 用户已确认降级，但来源应用无可解析入口。 | 否。 |
| `USER_DECLINED_FALLBACK` | 用户关闭失败界面或未选择降级。 | 否。 |
| `ITEM_NOT_FOUND` | 条目不存在或已被用户删除。 | 否。 |

### 5.3 动作尝试摘要

每次用户请求最多产生一条去敏尝试摘要：条目内部 ID、动作层、结果枚举、失败枚举和 UTC 时间。摘要不得保存标题、正文、完整 URI、内容 ID、`PendingIntent`、`Intent`、异常堆栈中的 payload 或用户路径。其保留上限由 B02 和 `SP-09` 锁定。

## 6. 解析状态机与精确规则

```text
IDLE
  └─ OPEN_EXACT
       ├─ 当前会话有运行时句柄 → SEND_RUNTIME
       │    ├─ accepted → EXACT_DISPATCH_ACCEPTED_RUNTIME
       │    └─ canceled / consumed / rejected → TRY_PERSISTENT
       └─ 无当前会话句柄 → TRY_PERSISTENT
            ├─ 有可尝试精确目标 → VALIDATE_AND_SEND_TARGET
            │    ├─ accepted → EXACT_DISPATCH_ACCEPTED_PERSISTENT
            │    └─ 全部失败 → EXACT_UNAVAILABLE
            └─ 无精确目标 → EXACT_UNAVAILABLE

EXACT_UNAVAILABLE
  ├─ 用户明确选择仅打开来源应用 → OPEN_APP_FALLBACK
  │    ├─ accepted → APP_LAUNCH_DISPATCH_ACCEPTED
  │    └─ 无入口 / 被拒绝 → APP_LAUNCH_UNAVAILABLE
  └─ 用户离开 → USER_DECLINED_FALLBACK
```

### 6.1 固定优先级

1. 只在 `runtimeSessionId` 与当前会话相等时尝试 `RUNTIME_PENDING_INTENT`。
2. 运行时句柄不存在、已取消、已消费或被安全策略拒绝后，按 `priority ASC, targetId ASC` 尝试 `PERSISTENT_EXACT_TARGET`。
3. 任一精确派发被系统接受后，本次解析立即结束；不得在同一次点击中继续启动另一目标。
4. 所有精确候选均失败后输出 `EXACT_UNAVAILABLE`，条目从默认收件箱移入“当前无跳转动作归档”；归档页为条目提供一次明确的按需重扫动作，但不得承诺成功。来源应用入口如保留，只能使用明确的非精确文案，且不得自动启动。
5. 归档重扫只处理系统当前仍存在的活动通知，并复用 A03/A05 身份归并；只有重新关联回原 `itemId` 的动作才可用于本次派发，禁止只按来源、标题或正文猜测目标。
6. 只有收到新的 `OPEN_APP_FALLBACK + GRANTED_IN_CURRENT_FAILURE_FLOW` 请求才执行 `APP_LAUNCH`。
7. Android 16 上发送外部 `PendingIntent` 必须发生在处理用户点击的可见 Activity，并通过 `ActivityOptions.MODE_BACKGROUND_ACTIVITY_START_ALLOW_IF_VISIBLE` 显式选择发送方后台启动模式；禁止裸 `send()`，也禁止为此使用 `ALLOW_ALWAYS` 在后台自动拉起界面。

### 6.2 持久目标校验

- URI 必须使用 `SP-03` 验证并版本化的 scheme、host、path 结构和目标包约束；未知 scheme 或超长/畸形 payload 输出 `UNSUPPORTED`。
- 内容 ID 必须先通过对应来源提取器的语法校验，再由受控启动适配器构造显式或限定包的 `Intent`。
- 启动前检查目标 Activity 可解析；不可解析输出 `NO_HANDLER`。
- Android 安全策略拒绝启动时输出 `SECURITY_REJECTED`，不得放宽组件导出或权限检查绕过。
- 网络不可用、来源应用未登录或页面加载失败若发生在系统已接受派发之后，不改写为 OMN 的“未派发”；A13 记录实际落页为错误页或未验证。

### 6.3 无年龄 TTL 与状态更新

- `capturedAt`、`lastAttemptAt`、`firstReceivedAt` 和当前时间之间的差值不得触发删除、跳过或失效。
- 运行时句柄只因进程会话结束而不可访问，或因实际 `CANCELED`、`CONSUMED`、`SECURITY_REJECTED` 结果改变当前会话状态。
- 持久目标只在用户实际点击后的可分类结果中更新 `validationState`；不得运行后台验证任务。
- `TEMPORARY_FAILURE` 不删除目标；下次用户点击仍可再次尝试。
- `PERMANENT_FAILURE` 只表示最近已验证的目标失效，目标记录随条目保留到用户删除；实现不得以此推导长期条目的自动清理。

## 7. 权限与生命周期边界

| 边界 | 预期行为 |
|---|---|
| 原系统通知被划除 | 长期条目和持久目标保留；运行时句柄是否仍可发送由实际结果决定。 |
| OMN Activity 重建 | 同一进程会话内可继续访问句柄；界面不得持有 framework 对象。 |
| OMN 进程重建 | 新建 `runtimeSessionId`；旧 `PendingIntent` 引用不可恢复，直接从持久精确目标开始。 |
| 来源应用普通进程结束 | 不预判句柄失效；用户点击时以实际发送与落页结果为准。 |
| 来源应用进入 stopped / 被强行停止 | 可能取消其 `PendingIntent` 或阻止启动；记录实际失败，不自动删除条目或持久目标。 |
| 来源应用更新 | 重新验证实际落页；既有目标不因版本号变化自动过期。 |
| 设备重启 | 运行时句柄必然不在 OMN 内存；只尝试持久精确目标，再由用户决定是否 `APP_LAUNCH`。 |
| 来源内容删除或权限变化 | 精确目标可能到达不存在/无权限页面；记录 `TARGET_MISSING` 或落页证据，不伪装成功。 |
| 来源应用卸载 | 精确 URI 和应用入口可能 `NO_HANDLER`；保留条目与目标，重装后允许再次尝试。 |
| 通知使用权撤销 | 影响未来采集，不禁止用户点击既有条目的受支持目标。 |
| `POST_NOTIFICATIONS` 拒绝 | 只影响 A10 状态通知可见性，不影响本功能跳转。 |

本功能不请求网络、无障碍、联系人、短信或广泛存储权限。对外部 URI、包名和通知字段一律按不可信输入校验。

## 8. Given / When / Then 验收条件

### 8.1 当前进程运行时动作

**Given** 条目属于当前 `runtimeSessionId`，且有未尝试的内容 `PendingIntent`
**When** 用户点击条目，系统接受 `PendingIntent.send()`
**Then** 输出 `EXACT_DISPATCH_ACCEPTED_RUNTIME`，不再启动持久目标，并把落页验证保持为 `NOT_OBSERVED`，直至真机验收记录实际落页。

### 8.2 运行时动作取消后转精确持久目标

**Given** 当前会话句柄发送返回取消，且条目有一个可解析的精确持久目标
**When** 用户点击条目
**Then** 先记录运行时 `CANCELED`，再尝试该持久目标；系统接受后输出 `EXACT_DISPATCH_ACCEPTED_PERSISTENT`。

### 8.3 进程重建不恢复句柄

**Given** 条目曾有运行时句柄，但 OMN 已重建进程
**When** 用户点击条目
**Then** 不读取或反序列化旧句柄，直接按固定顺序尝试精确持久目标。

### 8.4 不设置年龄期限

**Given** 两个条目除 `firstReceivedAt` 和 `capturedAt` 年龄外拥有相同可用持久目标
**When** 用户分别点击两个条目
**Then** 解析顺序和可尝试性完全相同，不因较旧条目跳过目标或显示“已过期”。

### 8.5 精确策略全部失败

**Given** 当前会话无句柄，且所有精确目标分别为无处理程序或已验证目标缺失
**When** 用户首次点击条目
**Then** 输出 `EXACT_UNAVAILABLE`，显示分类原因和独立降级按钮，不自动打开来源应用。

### 8.6 用户明确选择降级

**Given** 当前条目已显示精确跳转不可用，来源应用入口可解析
**When** 用户点击“仅打开来源应用”
**Then** 产生新的已确认降级请求，系统接受后输出 `APP_LAUNCH_DISPATCH_ACCEPTED`，界面和诊断均标为降级而非精确成功。

### 8.7 用户拒绝降级

**Given** 当前条目已显示精确跳转不可用
**When** 用户关闭提示而未点击降级按钮
**Then** 不启动任何应用，结果为 `USER_DECLINED_FALLBACK`。

### 8.8 首页或搜索页不算精确落页

**Given** 某策略的启动请求被系统接受
**When** 真机实际显示 B 站首页、推荐页或搜索结果，而非通知对应内容
**Then** `landingVerification` 为 `WRONG_TARGET_VERIFIED`，该用例不得计入精确跳转通过率。

### 8.9 归档条目按需重新获取动作

**Given** 条目当前没有运行时动作并位于“当前无跳转动作归档”
**When** 用户点击“尝试重新获取并打开（不一定成功）”
**Then** OMN 只执行一次当前活动通知重扫，并等待既有摄取队列完成
**And** 只有重扫按身份与生命周期重新关联到同一 `itemId` 时才立即尝试派发
**And** 未找到时提示“系统当前没有可重新取得的原通知动作”，不打开来源首页、不删除条目、不启动后台重试。

### 8.10 内容删除

**Given** 结构化目标仍可解析，但来源内容已删除
**When** 用户点击后实际到达“不存在”错误页
**Then** 条目仍保留，记录错误页落证；不得删除目标、条目或改写其首次接收时间。

### 8.11 来源应用未安装

**Given** 当前会话无可用句柄，来源应用无精确目标处理程序且无应用入口
**When** 用户尝试精确跳转并随后确认降级
**Then** 依次得到 `EXACT_UNAVAILABLE` 和 `APP_LAUNCH_UNAVAILABLE`，OMN 不崩溃且继续监听后续通知。

### 8.12 一次性动作已消费

**Given** 运行时动作已成功使用且被证据确认为一次性
**When** 用户再次点击同一条目
**Then** 不再次发送已消费句柄，转而尝试持久精确目标；没有精确目标时显示真实失败。

### 8.13 条目不存在

**Given** 用户操作时目标条目已被明确删除
**When** 跳转请求到达解析器
**Then** 输出 `ITEM_NOT_FOUND`，不尝试任何缓存句柄、URI 或来源应用入口。

## 9. 错误状态与用户文案

| 失败枚举 | 用户可见含义 | 是否允许显示降级按钮 |
|---|---|---:|
| `CANCELED` | 原通知动作已被来源或系统取消。 | 精确持久目标也失败后允许。 |
| `CONSUMED` | 原通知动作只能使用一次且已经用过。 | 精确持久目标也失败后允许。 |
| `NO_HANDLER` | 当前没有应用能处理该精确目标。 | 是。 |
| `TARGET_MISSING` | 已验证目标内容不存在或不可访问。 | 是。 |
| `UNSUPPORTED` | 该通知没有受支持的精确目标格式。 | 是。 |
| `SECURITY_REJECTED` | Android 拒绝了该启动请求。 | 只有来源应用入口可安全解析时允许。 |
| `UNKNOWN_FAILURE` | 跳转失败，但未取得可分类证据。 | 是；同时保留去敏诊断摘要。 |

文案必须说明“归档记录仍保留”。未知错误不得展示原始异常消息中的 URI、Token、组件名参数或本机路径。

## 10. 交互与无障碍

1. 整个通知条目或明确的“打开”按钮提供至少 48dp 触控范围；直接候选描述为“尝试打开原内容”，归档候选描述为“尝试重新获取并打开原内容，不一定成功”。
2. 精确策略失败后使用 Material 3 标准对话框或底部面板，展示失败原因、“仅打开来源应用”和“取消”两个明确动作。
3. `APP_LAUNCH` 按钮的无障碍标签必须包含“仅打开来源应用，可能不会到达原内容”。
4. 跳转可用、失效和降级不得只靠图标或颜色表达。
5. 字体最大、横竖屏、分屏、深浅色和动态配色下，失败原因和两个动作均可完整操作。
6. 系统接受启动后不显示“已到达原内容”的虚假 Toast；只有 A13 或其他受控验收可记录实际落页结论。

## 11. 隐私与性能约束

- 所有运行时动作和持久目标默认仅在设备本地应用边界内使用；本功能零网络、零遥测、零远程解析。
- 运行时句柄只在当前进程按内部条目 ID 索引，不复制进日志、数据库、崩溃报告或导出。
- URI 日志只允许输出目标类型、解析器版本和结果枚举；不得输出 scheme 后的完整值、查询参数或内容 ID。
- 点击时按需解析当前条目的动作摘要；不得为显示列表而加载全部历史目标或全部运行时句柄。
- 归档重扫只在用户点击时查询一次系统当前活动通知，并设有限等待；不得周期执行，也不得因失败自动重试。
- 不运行目标可用性轮询、周期清理、唤醒锁、精确闹钟或后台预热。
- 大量句柄的 PSS/Binder 成本由 `SP-02` 以 release 真机测量锁定；没有证据前不实施静默 LRU 淘汰，也不承诺无限保留。
- 任何性能优化不得改变固定优先级、吞掉失败分类或把 `APP_LAUNCH` 计为精确成功。

## 12. 测试要求

### 12.1 自动化测试

- 解析器表驱动测试覆盖三层优先级、运行时成功即停止、运行时失败转持久目标、精确失败不自动降级。
- 性质测试生成不同 `firstReceivedAt` 和 `capturedAt`，证明年龄不改变解析顺序或可尝试性。
- 进程会话测试证明旧 `runtimeSessionId` 的句柄不可访问且不会被反序列化。
- 持久目标解析测试覆盖允许/拒绝 scheme、超长字段、畸形 ID、无处理程序和安全拒绝。
- 多目标测试证明按 `priority ASC, targetId ASC` 确定执行，重复运行结果一致。
- 敏感信息测试用哨兵正文、标题、URI、Token、动作和路径，扫描日志及尝试摘要均不得出现哨兵。
- 失败隔离测试证明单条畸形目标不终止监听或阻塞其他条目跳转。
- UI 测试覆盖失败对话框、显式降级确认、TalkBack 标签、48dp 目标和最大字体。
- 按需恢复测试覆盖：同一 `itemId` 重获动作并派发、无活动通知时明确失败、重扫超时、不同生命周期不得误关联，以及条目从归档移出时本次用户操作仍继续完成。

### 12.2 红魔 11 Pro+ 真机测试

- 使用 release 构建记录原通知仍在、系统划除、立即尝试、跨日检查点、OMN 进程重建、来源应用普通进程结束/强行停止/更新和设备重启后的派发与实际落页。
- 对不同数量运行时句柄测量后台 PSS、Binder 相关证据和跳转成功率；样本数量与绝对门由 `SP-02` 锁定。
- 对投稿、动态、开播逐类验证持久目标在进程重建和重启后的实际落页；正式三类完成门见 A13。
- 覆盖无网络、未登录、内容删除、来源应用卸载/重装、无处理程序和一次性动作。
- 所有等待检查点只用于测量，不成为 TTL；报告必须明确这一点。
- 模拟器可验证解析规则，不能替代 `PendingIntent` 寿命、来源应用状态和实际落页结论。

## 13. Phase 0 Spike 与决策门

### 13.1 `SP-02 原始动作寿命与持有成本`

必须回答：运行时动作在系统通知仍在、划除、等待、OMN 进程存活、来源应用普通进程结束/强行停止/更新和不同句柄数量下的实际行为与资源成本。证据必须同时记录系统是否接受派发和实际落页，不能只记录 `send()` 无异常。

### 13.2 `SP-03 B 站持久精确目标`

必须回答：投稿、动态、开播各自能否提取可跨 OMN 进程和设备重启保存的结构化目标；每类输出只能是“精确持久目标”“仅当前进程精确动作”或“不支持”，并列出未登录、内容删除和客户端更新反例。

### 13.3 `SP-09 持久化、隐私与性能基线`

必须证明：运行时句柄未进入 Room、文件、日志或导出；持久目标没有任意序列化 `Intent`；跳转尝试摘要有界；release 真机句柄成本和点击路径满足锁定预算。本文不锁定或实施 Room entity、列、索引、schema 版本或迁移。

### 13.4 决策门

- **GO**：至少一个 `v0.1` 受支持真实样本在“系统划除 → OMN 查找 → 实际精确落页”闭环通过；三层结果可区分；年龄不触发失效；持久化与隐私边界通过扫描；资源成本可被预算约束。
- **REDIRECT**：只能在当前进程内精确跳转、持久目标覆盖不足，或句柄成本要求受控容量；先更新能力声明、产品边界和相关规格，再由用户确认。
- **STOP**：所有真实样本只能打开来源应用首页/搜索页，或精确跳转只能依赖不受支持的令牌持久化、私有 API、联网抓取或违反资源预算的方案。

A09 只有在 Phase 0 得出 `GO`，自动化测试通过，并在红魔 11 Pro+ release 构建完成至少一个受支持样本的实际精确落页后，才可在 `v0.1` 标记完成。B 站三类全部通过仍由 A13 在 `v0.4` 阻断验收。
