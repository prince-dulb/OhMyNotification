# A12 多应用查看筛选

状态：`[已确认] plan-v1.0 基线；Phase 0 未决项保持待验证`

## 1. 规格元数据

| 项目 | 值 |
|---|---|
| 功能 ID | `A12` |
| 优先级 | `[A]` |
| 主交付版本 | `v0.2` |
| 前置功能 | `A06 稳定排序`、`A08 本地持久化` |
| 被依赖功能 | `A07 时间窗应用抽屉`、`A13 B 站端到端真机验收`、`B01 关键词与时间筛选` |
| 相关 Spike | `SP-08（架构 S7）排序、抽屉、筛选与分页`、`SP-09（架构 S8）持久化、隐私与性能基线` |

本规格只控制当前收件箱查询的来源集合。它与 `A02 应用排除列表` 没有写入依赖，也不改变监听、采集或持久化。

## 2. 目标与非目标

### 2.1 目标

- 用户可以查看全部历史，或同时选择一个或多个来源查看其历史条目。
- 来源身份包含 Android 用户与包名；同包名在个人资料和工作资料中可分别选择。
- 查看条件在本地查询层先过滤，再按 A06 稳定排序、分页并交给 A07 分组。
- 应用进程重建后恢复最后一次已应用的来源筛选。
- 切换、清空或恢复筛选不影响任何通知采集事实和监控策略。

### 2.2 非目标

- 不停止或恢复任何应用的通知采集。
- 不删除、不归档、不改写被隐藏条目。
- 不按关键词或时间筛选通知正文；该能力属于 B01。
- 不在设置页复用 A02 的排除开关或状态对象。
- 不为筛选运行后台任务、网络请求或遥测。

## 3. 术语与不变量

| 术语 | 精确定义 |
|---|---|
| `AppUserKey` | `sourceUser + sourcePackage` 的复合来源键。 |
| `includedSources` | 当前查看筛选的来源白名单；非空时只查看这些来源。 |
| `excludedSources` | 当前查看筛选的来源黑名单；仅在白名单为空时生效。两个集合都为空表示“查看全部”。 |
| 查看全部 | 查询不增加来源谓词，而不是把当前所有来源复制进集合。新来源历史也会自动可见。 |
| 查看筛选 | 只读查询条件 `InboxFilter`；不会传入 `NotificationListenerAdapter` 或 `MonitoringPolicySnapshot`。 |
| 选项搜索 | 只在多选面板中过滤来源名称/包名的临时文本，不搜索通知内容。 |

全局不变量：

1. `InboxFilter.includedSources` 非空时表示来源键的 OR 集合，`excludedSources` 必须为空。
2. 白名单为空时显示不属于 `excludedSources` 的来源；两个集合都为空表示全部。
3. `InboxFilter` 与 `MonitoringPolicy` 使用不同模型、用例、仓储和持久化键。
4. 修改查看筛选不得读写 `MonitoringPolicyRepository`，不得改变 `MonitoringPolicy.revision`。
5. 修改监控排除不得改写当前 `includedSources` 或 `excludedSources`。
6. 查看筛选只缩小当前查询集合；通知条目、事件、动作、排序键和健康证据保持不变。
7. A06 基础全序先对命中集合生效；A07 只对筛选后的当前可见流分组。

## 4. 输入与输出契约

### 4.1 `AppUserKey`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `sourceUser` | `AndroidUserRef` | 是 | 不得用当前用户隐式代替。 |
| `sourcePackage` | `PackageName` | 是 | 非空，按包名精确匹配。 |

### 4.2 `InboxFilter`

与架构模型一致：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `includedSources` | `Set<AppUserKey>` | 是 | 非空为 OR；与 `excludedSources` 不得同时非空。 |
| `excludedSources` | `Set<AppUserKey>` | 是 | 白名单为空时按精确来源排除；空表示不排除。 |
| `timeRange` | `ClosedRange<InstantUtc>?` | 否 | A12 不修改；B01 可提供时间范围。 |

关键词不写入 `InboxFilter`；B01 将规范关键词放入 `InboxQueryCriteria.keyword`，并将时间范围放入 `InboxFilter.timeRange`。

### 4.3 `ApplyIncludedSourcesCommand`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `includedSources` | `Set<AppUserKey>` | 是 | 用户在多选面板按“应用”时提交；空为清除来源限制。 |
| `excludedSources` | `Set<AppUserKey>` | 是 | 来源菜单“不查看此 App”提交；与白名单互斥。 |

### 4.4 `ApplyIncludedSourcesResult`

| 结果 | 输出字段 | 含义 |
|---|---|---|
| `APPLIED` | `includedSources: Set<AppUserKey>`、`excludedSources: Set<AppUserKey>`、`queryFingerprint: InboxQueryFingerprint` | 来源偏好已本地保存，并与当前 B01 条件重新组合后启动新查询代。 |
| `NO_CHANGE` | `includedSources: Set<AppUserKey>`、`excludedSources: Set<AppUserKey>`、`queryFingerprint: InboxQueryFingerprint` | 来源集合与当前值相同；不写盘、不重启查询。 |
| `PERSISTENCE_FAILED` | `errorCode: ViewFilterErrorCode` | 旧筛选继续生效；不得显示新筛选已应用。 |

每个结果变体列出的输出字段均为该变体必填；未列出的变体字段不得返回。

### 4.5 `AvailableSourceOption`

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `source` | `AppUserKey` | 是 | 选项稳定键。 |
| `sourceLabel` | `String` | 是 | 使用最近保存标签；缺失时回退包名。 |
| `profileLabel` | `String?` | 否 | 多 Android 用户时用于区分。 |
| `iconRef` | `PackageName` | 是 | 按包名加载有界缓存图标。 |
| `hasSavedItems` | `Boolean` | 是 | 由本地长期条目事实得出。 |

选项来源是本地长期条目中的不同 `AppUserKey`，再并入当前已选择但暂时无可查询条目的键。来源应用卸载不删除选项或筛选状态。

### 4.6 查询输入与输出

`InboxQueryCriteria`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `inboxFilter` | `InboxFilter` | 是 | 两个来源集合来自 A12 最后一次 `APPLIED` 值；`timeRange` 由 B01 提供或为空。 |
| `keyword` | `SearchKeyword?` | 否 | B01 提供；未启用或已清除时为空。 |

两个 `InboxQueryFingerprint` 相等，当且仅当其 `includedSources`、`excludedSources` 集合、UTC `timeRange` 和规范关键词值都相等；集合迭代顺序、原始关键词、应用标签、设备时区显示格式和 `PagingGenerationId` 不参与该相等性。

查询输出使用以下最小 `NotificationItemSummary`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `itemId` | `ItemId` | 是 | 不变稳定键。 |
| `sourcePackage` | `PackageName` | 是 | 来源匹配字段。 |
| `sourceUser` | `AndroidUserRef` | 是 | 来源匹配字段。 |
| `sourceLabelSnapshot` | `String?` | 否 | 只供展示与 B01 搜索，不参与来源匹配。 |
| `firstReceivedAt` | `InstantUtc` | 是 | 主排序键。 |
| `ingestSequence` | `StableSequence` | 是 | 次排序键。 |
| `title` | `String?` | 否 | 只供展示。 |
| `body` | `String?` | 否 | 只供展示。 |
| `lastUpdatedAt` | `InstantUtc` | 是 | 只供行内容刷新，不参与排序。 |
| `actionState` | `ActionStateSummary` | 是 | 只供展示和点击状态。 |

`SourceFilteredInboxResult`：

| 字段 | 类型 | 必填 | 约束 |
|---|---|---:|---|
| `queryFingerprint` | `InboxQueryFingerprint` | 是 | 对应当前已应用条件。 |
| `activeFilter` | `InboxFilter` | 是 | 与查询条件一致。 |
| `items` | `PagedOrderedStream<NotificationItemSummary>` | 是 | 惰性分页结果。 |
| `isEmpty` | `Boolean` | 是 | 当前条件无命中时为 `true`。 |

`items` 必须满足：

- 只含命中来源白名单，或在白名单为空时未命中来源黑名单的条目。
- 按 `firstReceivedAt DESC, ingestSequence DESC, itemId DESC`。
- 不含重复 `itemId`，分页边界不漏项、不改序。

## 5. 规则与状态

### 5.1 来源匹配

```text
matchesSource(item, includedSources, excludedSources) =
    if includedSources.isNotEmpty():
        AppUserKey(item.sourceUser, item.sourcePackage) ∈ includedSources
    else:
        AppUserKey(item.sourceUser, item.sourcePackage) ∉ excludedSources
```

- 非空集合使用 OR：选择 A、B 表示显示 A 或 B，不要求同时属于两者。
- 在应用抽屉标题行选择“仅查看此 App”时，应用 `{当前来源}` 白名单并清空查看黑名单。
- 在应用抽屉标题行选择“不查看此 App”时，把当前来源从可见范围排除；处于“查看全部”时必须保存为黑名单，不能把当时已知的其他 App 固化成白名单，否则以后出现的新来源也会被意外隐藏。
- 两个快捷操作与 A02 的监控操作共用来源级菜单，但查看操作不得改变采集策略。
- 不按应用标签匹配；标签变化不改变来源键。
- 被 A02 排除的来源仍可通过本地既有条目成为选项并显示历史。

### 5.2 多选面板状态机

```text
ACTIVE(appliedSet)
  → 打开面板 → EDITING(draftSet = appliedSet)
      ├─ 切换选项/搜索选项 → EDITING(draftSet)
      ├─ 取消/返回           → ACTIVE(appliedSet)
      ├─ 清除               → EDITING(emptySet)
      └─ 应用               → SAVING
                                  ├─ 成功 → ACTIVE(newSet) + 新查询代
                                  └─ 失败 → EDITING(draftSet) + ERROR
```

- 面板中的选项搜索只改变选项可见性，不从 `draftSet` 移除被暂时隐藏的已选项。
- 只有按“应用”并收到 `APPLIED` 才更新当前列表。
- 新筛选创建新的 `queryFingerprint`，废弃旧分页游标与旧 A07 分组 continuation。
- 最后一次 `APPLIED` 的 `includedSources` 与 `excludedSources` 原子保存在应用私有查看偏好中；不得与通知数据自动备份或跨设备迁移。

### 5.3 页面状态

| 状态 | 行为 |
|---|---|
| `FILTER_LOADING` | 尚不能确定最后筛选时，不显示可能泄露范围更大的列表。 |
| `SHOWING_ALL` | 两个来源集合都为空；顶部显示“全部应用”。 |
| `SHOWING_SELECTED` | 非空；顶部显示选中数量或可读摘要。 |
| `HIDING_SELECTED` | 白名单为空且黑名单非空；顶部显示隐藏来源数量。 |
| `EMPTY_RESULT` | 明确显示“当前查看条件没有记录”，不解释为监听失败。 |
| `FILTER_ERROR` | 保持最后成功列表，显示保存/查询错误与重试。 |

## 6. 用户故事与交互

### 6.1 用户故事

- 作为用户，我要只看 B 站历史，同时继续记录其他未排除应用。
- 作为用户，我要同时看 B 站和短信，且结果保持统一时间顺序。
- 作为用户，我要查看已经停止监控应用的旧记录。
- 作为拥有工作资料的用户，我要区分同包名在两个资料中的历史。

### 6.2 交互要求

- 收件箱顶部提供 Material 3 筛选入口；有效触控范围至少 48dp。
- 每个时间轴应用抽屉的标题行在展开/收起控件旁提供来源级“更多”菜单；抽屉内单条通知不重复显示来源菜单。
- 应用较多时使用可搜索多选底部面板，不在顶部横向堆满标签。
- 选项行向无障碍服务报告应用名、资料和是否已选择；该面板不读取或展示 A02 开关，也不提供监控操作。
- 清除来源筛选后显示全部记录；不自动清除 B01 的关键词或时间条件。
- 最大字体、横竖屏、分屏和输入法弹出时，“应用”“取消”“清除”仍可到达。

## 7. Given / When / Then 验收

### AC-A12-01 空集合查看全部

- Given `includedSources` 为空且本地有 A、B、C 三个来源条目
- When 查询收件箱
- Then A、B、C 都按 A06 基础全序出现
- And 新出现的来源 D 无需修改集合也可显示

### AC-A12-02 多来源 OR

- Given 本地有 A、B、C 条目
- When 用户应用 `{A, C}`
- Then 结果只含 A 或 C
- And A、C 之间保持 A06 基础相对顺序

### AC-A12-03 Android 用户隔离

- Given 个人资料与工作资料都有包名 P 的历史
- When 只选择 `AppUserKey(work, P)`
- Then 只显示工作资料 P
- And 不显示个人资料 P

### AC-A12-04 被排除来源历史仍可查看

- Given A 已有历史且 `MonitoringPolicy.userExcludedSources={A}`
- When 用户把 A 作为唯一查看来源
- Then A 的既有记录正常显示
- And A 的未来通知仍按 A02 排除

### AC-A12-05 查看筛选不影响采集

- Given 当前只查看 A，B 未被监控排除
- When B 的通知到达
- Then B 仍被采集和持久化
- And 当前列表不显示 B
- When 用户清空查看筛选
- Then 已保存的 B 出现在正确时间位置

### AC-A12-06 修改查看条件不写监控策略

- Given `MonitoringPolicy.revision=12`
- When 用户依次应用 `{A}`、`{A,B}`、空集合
- Then `MonitoringPolicy.revision` 始终为 12
- And `userExcludedSources` 始终不变

### AC-A12-07 修改监控策略不写查看条件

- Given 当前 `includedSources={A}`
- When 用户在 A02 排除或恢复 B
- Then `includedSources` 仍为 `{A}`
- And 当前查询范围不变

### AC-A12-08 取消不应用草稿

- Given 已应用 `{A}`
- When 用户在面板草稿选择 B 并点击取消
- Then 当前筛选仍为 `{A}`
- And 不产生查看偏好写入或新查询代

### AC-A12-09 筛选变化重建分页与抽屉

- Given 旧查询已加载多页并形成抽屉
- When 用户应用新的来源集合
- Then 旧分页游标和分组 continuation 被丢弃
- And 新结果从首屏按新 `queryFingerprint` 产生
- And 不混入旧条件条目

### AC-A12-10 进程重建恢复

- Given 最后成功应用 `{A,B}`
- When 终止并重建 OMN 进程
- Then 在显示收件箱内容前恢复 `{A,B}`
- And 查询结果与重建前条件相同

### AC-A12-11 卸载来源仍可看历史

- Given A 有历史后被卸载
- When 用户打开来源筛选并选择 A
- Then 以保存标签或包名显示 A 选项
- And A 的历史仍可查询

### AC-A12-12 与 B01 组合

- Given 来源筛选 `{A,B}` 且 B01 时间条件命中 A1、B1、C1
- When 执行组合查询
- Then 结果只含 A1、B1
- And 条件顺序不改变逻辑 AND 结果或 A06 排序

## 8. 边界条件与错误状态

| 场景/错误码 | 用户可见状态 | 系统行为 |
|---|---|---|
| `FILTER_LOAD_FAILED` | 显示“无法读取上次查看范围”，提供重试和用户明确选择“查看全部” | 在用户选择前不默认扩大可见范围。 |
| `FILTER_SAVE_FAILED` | 面板保留草稿并显示“未应用” | 旧筛选和旧查询继续生效。 |
| `QUERY_FAILED` | 保留最后成功页面并显示“重试”操作 | 只在用户点击后重新发起一次查询；不修改筛选、不自动循环、不全表加载兜底。 |
| 选中来源当前无记录 | 显示当前范围无记录 | 保留选中状态，不改成全部。 |
| 来源卸载/标签缺失 | 显示包名与占位图标 | 仍按 `AppUserKey` 查询。 |
| 工作资料暂停/不可用 | 显示资料当前不可用说明 | 保留筛选，不映射到个人资料。 |
| 选项搜索为无结果 | 面板显示“没有匹配的应用” | 已选但被搜索隐藏的来源仍在草稿集合。 |
| 查询代失效 | 短暂重新加载首屏 | 不复用旧游标或旧抽屉成员。 |

## 9. 数据流与隔离边界

```text
查看路径：
用户选择来源
  → ApplyIncludedSourcesCommand
  → InboxViewPreferencesRepository（仅查看偏好）
  → InboxQueryCriteria
  → InboxQuery / PagingSource
  → A06 稳定排序
  → A07 时间窗分组
  → Compose UI

采集路径（完全独立）：
系统回调
  → MonitoringPolicySnapshot（A02）
  → NotificationSnapshotFactory
  → NotificationIngestionCoordinator
  → NotificationRepository
```

两条路径不得共享写命令。`InboxQuery` 没有 `MonitoringPolicyRepository` 写端口，监听服务也不读取 `InboxFilter`。

## 10. 隐私与性能要求

- 来源筛选只保存在应用私有空间，并排除 Android 自动云备份和跨设备自动迁移。
- 选项搜索文本是临时 UI 状态，不记录日志、不持久化、不联网。
- 筛选不复制通知正文，不生成第二份结果缓存，不写 `NotificationItem`。
- 多来源查询必须在 Room/Paging 查询层完成，按来源键与基础排序键分页；不得加载全表后在 UI 过滤。
- 10,000 条场景覆盖全部、单选、多选、空结果、快速切换和返回列表；记录查询范围、已加载数、首屏、筛选耗时和 PSS。
- 筛选变化只重算新查询的必要页与时间轴窗口；无筛选操作时不产生周期工作、网络、写盘或唤醒。
- Phase 0 锁定绝对查询预算；同场景筛选耗时或后台内存无解释回退超过 10% 时不得通过。

## 11. 测试要求

### 11.1 自动化测试

- 纯规则测试：空集合为全部、非空 OR、`AppUserKey` 用户隔离、标签变化不影响匹配。
- 仓储测试：最后应用状态持久化、`NO_CHANGE` 不写盘、保存失败保持旧状态、进程重建恢复。
- 架构边界测试：查看用例没有监控策略写依赖；监听适配器没有 `InboxFilter` 依赖。
- 查询测试：全部/单选/多选与 A06 排序、分页、A07 分组、B01 条件组合。
- 竞态测试：筛选期间其他来源新通知仍持久化；新查询代不混用旧页。
- Compose 测试：草稿、应用、取消、清除、选项搜索、错误态、48dp、TalkBack、最大字体、横竖屏和分屏。

### 11.2 真机测试

- 红魔 11 Pro+、release 构建用至少三个真实来源验证全部、单选和多选。
- 只查看 A 时向 B 发送通知，确认 B 后台仍被记录；清空筛选后可见。
- 排除一个仍有历史的来源，确认其旧记录可筛选、新通知不采集。
- 覆盖进程重建、来源卸载；设备支持时覆盖工作资料。
- 10,000 条生成数据执行快速切换、连续翻页、抽屉展开和返回列表，记录性能指标。

## 12. Spike 决策门

- `SP-08` 必须证明：多来源筛选前置于分组、切换筛选可预测、分页不重复/漏项/改序，且不同页大小得到相同结果。
- `SP-09` 必须锁定：查看偏好存储与自动备份边界、来源 + 排序键查询预算、10,000 条 PSS 和首屏/筛选耗时。
- 任一门未通过时 A12 不得以 UI 标签能切换为完成；必须同时证明采集不受影响和查询结果稳定。
