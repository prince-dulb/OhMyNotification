# A13 B 站端到端真机验收规格说明

- **主交付版本**：`v0.4`
- **优先级**：`[A]`
- **规格状态**：`[已确认] plan-v1.0 基线；Phase 0 未决项保持待验证`
- **Phase 0 依赖**：`SP-01 真实通知字段与生命周期`、`SP-02 原始动作寿命与持有成本`、`SP-03 B 站持久精确目标`、`SP-04 摄取队列、事务与归并`、`SP-05 监听可靠性与红魔后台策略`、`SP-06 状态通知与前台服务 A/B`
- **功能依赖**：A01—A12 全部功能、A14 的测量协议与锁定预算
- **被依赖**：`v0.4` `[A]` 级 MVP 完成声明、`v0.5` 及以后 B 站阻断性回归

## 1. 目标与范围

本功能不是新的后台机制，而是一套阻断性真机验收：在红魔 11 Pro+、Android 16、release 构建上，以 B 站真实“投稿”“动态”“开播”通知证明 OMN 的完整日用链路。

每一类都必须完成：

```text
真实通知到达
→ OMN 提交唯一长期条目
→ 常驻状态通知显示已提交摘要
→ 用户划除原系统通知
→ 稍后在正确全局时间位置或抽屉内找到该条目
→ 点击条目
→ 真机实际落到该通知对应的投稿、动态或直播间
```

`[已确认]` 三类各至少有一次完整精确落页通过，A13 才能通过。只打开 B 站首页、推荐页、搜索结果、错误页，或只观察到 `PendingIntent.send()`/`startActivity()` 没有抛错，均不算精确落页。

`[已确认]` 本规格同时覆盖动作与来源状态的失效边界。失效边界允许得到“精确不可用”或“仅打开来源应用”的真实结果，但不得崩溃、删除归档条目或把降级伪装成精确成功。

### 1.1 本功能不做

- 不用自制通知、截图、模拟器或手工插入数据库替代三类真实 B 站通知的主闭环。
- 不以 B 站账号登录、私有 API、网页抓取或 OMN 主动联网触发/补全通知。
- 不把等待检查点变成人为 TTL，不因通知变旧自动失败。
- 不为方便测试关闭去重、放宽目标匹配或绕过 Android 安全限制。
- 不把真实标题、正文、BV/AV 号、动态 ID、直播间 ID、账号、动作或截图提交到 Git。
- 不在本文锁定或实施 Room entity、表、列、索引、schema 版本或迁移。

## 2. 术语与通过口径

### 2.1 通知类型

| `BilibiliNotificationKind` | 定义 | 精确落页身份 |
|---|---|---|
| `SUBMISSION` | UP 主投稿/视频发布推送。 | 实际打开的视频身份与通知预期视频身份一致。 |
| `DYNAMIC` | UP 主或关注对象的动态推送。 | 实际打开的动态身份与通知预期动态身份一致。 |
| `LIVE_START` | 关注主播开播推送。 | 实际打开的直播间身份与通知预期直播间身份一致；直播已结束时到达同一房间的已结束页仍算目标身份一致。 |

### 2.2 结果术语

| 术语 | 定义 |
|---|---|
| 真实通知 | 由当前安装的官方 B 站客户端通过 Android 通知系统实际发布，并由 OMN 监听回调观察到的通知。 |
| 唯一条目 | 同一通知生命周期的发布/更新最终只有一个 `NotificationItem`；不同内容不得被合并。 |
| 实际落页 | 测试人员在目标真机上看到并按本地预期身份核对的最终页面。 |
| 精确通过 | `landingVerification = EXPECTED_TARGET_VERIFIED` 且身份匹配规则通过。 |
| 降级通过 | 系统与 UI 正确标为 `APP_LAUNCH`，未宣称精确；它只通过失效处理用例，不通过三类主闭环。 |
| `NOT_OBSERVED` | 需要的真实通知、系统状态或落页没有取得证据；不得换算为通过。 |
| 无效用例 | 构建、设备、时间、来源版本、前置状态或证据链缺失，导致结果不能复现。 |

## 3. 用户故事

- 作为 B 站用户，我划掉投稿推送后，仍能从 OMN 找到唯一记录并进入那一个视频。
- 作为 B 站用户，我划掉动态推送后，仍能进入那一条动态，而不是作者主页或搜索页。
- 作为 B 站用户，我稍后查看开播推送时，仍能进入该主播对应直播间；直播结束可以显示同一房间的结束状态。
- 作为长期使用者，我希望进程重建、重启、B 站状态变化或目标失效时，OMN 显示真实能力，不用首页跳转掩盖失败。

## 5. 输出契约

### 5.1 `BilibiliE2eResult`

| 字段 | 逻辑类型 | 必填 | 规则 |
|---|---|---:|---|
| `caseAlias` | `String` | 是 | 公开安全的非可逆别名。 |
| `kind` | `BilibiliNotificationKind` | 是 | 与输入一致。 |
| `boundaryCase` | `BoundaryCase` | 是 | 与输入一致。 |
| `status` | `AcceptanceStatus` | 是 | `PASS`、`FAIL`、`NOT_OBSERVED` 或 `INVALID_CASE`。 |
| `logicalItemCount` | `NonNegativeInt` | 是 | 该生命周期最终关联的长期条目数量；主闭环必须为 1。 |
| `dispatchOutcome` | `JumpOutcome?` | 否 | A09 的派发结果；未点击时为空。 |
| `landingVerification` | `LandingVerification` | 是 | `EXPECTED_TARGET_VERIFIED`、`WRONG_TARGET_VERIFIED`、`ERROR_PAGE_VERIFIED` 或 `NOT_OBSERVED`。 |
| `selectedLayer` | `JumpLayer?` | 否 | 运行时、持久精确目标或 `APP_LAUNCH`。 |
| `healthConsistency` | `Boolean` | 是 | A01/A11 五个事实维度与实际操作是否一致。 |
| `statusNotificationConsistency` | `Boolean` | 是 | A10 摘要是否只使用已提交事实且锁屏脱敏。 |
| `checkpoints` | `List<E2eCheckpoint>` | 是 | 按实际时序排列；缺一步不得补写。 |
| `failureReason` | `AcceptanceReason?` | 否 | `FAIL`、`NOT_OBSERVED` 或 `INVALID_CASE` 时必填。 |

### 5.2 三类主闭环通过规则

一个 `PRIMARY_DISMISSED_FLOW` 用例只有同时满足以下条件才为 `PASS`：

1. 通知由真实 B 站客户端发布并被 OMN 监听回调观察；
2. 持久化成功后只形成一个逻辑条目；
3. A10 最近记录摘要来自该已提交变化，锁屏不暴露标题或正文；
4. 用户实际划除原系统通知；
5. 条目按 `firstReceivedAt DESC` 的稳定规则出现在正确位置，若进入抽屉则抽屉范围和内部逐条时间正确；
6. 用户点击的是该条目，不是重新从系统通知点击；
7. 实际落页身份与本地 `expectedTarget.privateIdentity` 相同；
8. `selectedLayer` 为运行时动作或持久精确目标，不得为 `APP_LAUNCH`；
9. 全程没有把通知正文、动作或目标写入公开证据。

`SUBMISSION`、`DYNAMIC`、`LIVE_START` 各至少有一个上述用例通过；任一类型只有降级或 `NOT_OBSERVED` 时，A13 失败。

### 5.3 公开验收摘要

公开或 Git 跟踪的结果只允许包含：构建版本、设备型号、Android 版本、B 站版本、用例别名、通知类型、边界枚举、时间、结果枚举、动作层、计数、性能摘要和已知限制。不得包含真实标题、正文、账号、内容 ID、完整 URI、动作、截图、本机路径或设备唯一标识。

## 6. 流程、状态机与覆盖矩阵

### 6.1 主流程状态机

```text
WAITING_REAL_NOTIFICATION
  ├─ 未取得真实通知 → NOT_OBSERVED
  └─ callback observed → INGESTING
       ├─ commit failed → FAIL
       └─ item committed → VERIFY_STATUS_SUMMARY
            ├─ 摘要错误 / 泄露 → FAIL
            └─ 正确 → DISMISS_SYSTEM_NOTIFICATION
                 ├─ 未实际划除 → INVALID_CASE
                 └─ 已划除 → LOCATE_ARCHIVE_ITEM
                      ├─ 未找到 / 重复 / 顺序错误 → FAIL
                      └─ 找到唯一条目 → OPEN_AND_VERIFY
                           ├─ 精确身份一致 → PASS
                           ├─ 首页 / 搜索 / 错误页 / 错内容 → FAIL
                           └─ 无落页证据 → NOT_OBSERVED
```

### 6.2 `BoundaryCase` 与最小覆盖

| 边界值 | 操作与观察 | 覆盖要求 | 可接受结论 |
|---|---|---|---|
| `PRIMARY_DISMISSED_FLOW` | 真实通知到达后划除，再从 OMN 打开。 | 投稿、动态、开播各 1 个 `PASS`。 | 只接受精确落页。 |
| `ORIGINAL_NOTIFICATION_PRESENT` | 原系统通知仍在时从 OMN 点击。 | 三类各至少 1 次。 | 精确落页或有证据失败；不得借用系统通知点击。 |
| `OMN_PROCESS_RECREATED` | 条目提交后终止并重建 OMN 进程。 | 三类各至少 1 次。 | 运行时句柄不可恢复；持久精确目标实际落页或真实失败。 |
| `DEVICE_REBOOTED` | 条目提交后重启设备，再从 OMN 打开。 | 三类各至少 1 次。 | 与进程重建相同；不允许序列化动作恢复。 |
| `SOURCE_PROCESS_NORMAL_GONE` | B 站普通进程结束但未进入 stopped。 | 三类各至少 1 次。 | 记录运行时/持久层实际表现，不预判。 |
| `SOURCE_FORCE_STOPPED` | B 站被用户强行停止并确认 stopped 状态。 | 至少覆盖运行时动作与持久目标各 1 个用例；三类能力表逐类给出结论。 | 允许取消、拒绝或失败；不得伪装成功，重新手动启动后可另测恢复。 |
| `SOURCE_UPDATED` | 保存条目后更新 B 站客户端版本。 | 三类各至少 1 次，允许复用同一次更新批次。 | 实际落页或路由失效分类。 |
| `WAIT_CHECKPOINT` | 在 `SP-02` 预注册的跨日或更长检查点点击。 | 三类各覆盖所有已锁定检查点。 | 年龄本身不得阻止尝试；结果按实际动作状态记录。 |
| `RUNTIME_ACTION_CANCELED` | 实际观察到 `CanceledException` 或等价取消。 | 每种被 Phase 0 判为依赖运行时动作的类型至少 1 次；没有可触发样本记 `NOT_OBSERVED`。 | 自动尝试持久精确目标，或明确精确不可用。 |
| `ONE_SHOT_CONSUMED` | 实际观察到一次性动作成功后再次点击。 | 对 Phase 0 发现一次性动作的每种类型各 1 次；未发现则 `NOT_APPLICABLE` 并附 `SP-02` 证据。 | 不再次发送已消费句柄。 |
| `CONTENT_UNAVAILABLE` | 目标内容删除、私密、下架或直播间不可访问。 | 三种目标结构各至少 1 个可复现用例；真实内容不可控时可使用经 `SP-03` 验证的同路由失效目标，但不能替代主闭环。 | 错误页/目标缺失；条目保留。 |
| `LOGGED_OUT` | B 站退出登录后点击。 | 三类各至少 1 次。 | 精确身份一致、登录页或权限页均按实际记录；只有身份一致才算精确通过。 |
| `OFFLINE` | 关闭设备网络后点击。 | 三类各至少 1 次。 | OMN 派发与来源加载失败分开；不得把网络错误当作记录不存在。 |
| `SOURCE_UNINSTALLED` | 卸载 B 站后尝试精确与降级，再重装复测。 | 三类既有目标各 1 次，可在同一卸载批次执行。 | 卸载时 `NO_HANDLER`；条目和目标保留；重装后允许再次尝试。 |
| `LISTENER_ACCESS_REVOKED` | 撤销通知使用权后点击既有条目并观察未来采集。 | 至少 1 个既有条目 + 1 个新通知观察。 | 既有跳转仍可尝试；新通知不得声称已记录。 |
| `LISTENER_RECONNECTED` | 断连、重连与活动通知补扫。 | 三类中至少 1 个活动样本和 1 个断连期消失反例。 | 补扫不重复；消失样本不得声称找回。 |
| `STATUS_PERMISSION_OR_CHANNEL_OFF` | 分别拒绝 `POST_NOTIFICATIONS`、关闭状态渠道。 | 两种状态各 1 次。 | 监听事实独立；应用内说明正确，状态卡不可见不等于未监听。 |

“至少”数量是覆盖下限，不表示绝对性能预算。无法自然取得的真实通知或不可控状态必须保留为 `NOT_OBSERVED`，不得用推测补齐；主闭环三类中的任何 `NOT_OBSERVED` 都阻断 A13。

### 6.3 确定性判定顺序

1. 先验证用例前置条件和真实通知来源；不满足则 `INVALID_CASE`。
2. 再核对监听回调、数据库提交和条目唯一性；任一失败即 `FAIL`，不继续用跳转成功掩盖采集失败。
3. 再核对 A10 摘要、列表排序/抽屉和 A11 健康事实；错误分别记为对应功能回归。
4. 最后执行 A09 跳转并核对实际落页；派发成功但落页未知为 `NOT_OBSERVED`，落到错误目标为 `FAIL`。
5. 失效边界的降级结果只通过该边界的错误处理，不计入三类精确主闭环。

## 7. 权限与生命周期边界

- 通知使用权决定未来真实通知是否可采集；`POST_NOTIFICATIONS` 只决定 A10 状态通知可见性；渠道、监听连接和进程证据分别记录。
- 用例开始前必须记录五个维度，状态中途变化必须形成检查点，不能用“权限正常”单一布尔值代替。
- OMN 进程重建与设备重启后，运行时 `PendingIntent` 必须视为内存不可达；验证路径只能依赖持久精确目标或明确降级。
- B 站普通进程结束、stopped、更新、卸载、未登录和网络离线是不同边界，结果不得合并成“B 站异常”。
- A10 普通常驻通知即使残留也不是 OMN 实时存活证明；用例必须对照监听连接和正面运行证据。
- 若 `SP-06` 选择 FGS，A13 只使用已验证、合法且符合资源门的生产拓扑；不得为了验收临时增加另一常驻服务。

## 8. Given / When / Then 验收条件

### 8.1 投稿主闭环

**Given** 红魔 11 Pro+ 收到一条真实投稿通知，预期视频身份已在本机记录
**When** OMN 提交条目、用户划除系统通知并从 OMN 点击该唯一条目
**Then** 实际落页视频身份必须一致；首页、搜索页、其他视频或无落页证据均不通过。

### 8.2 动态主闭环

**Given** 红魔 11 Pro+ 收到一条真实动态通知，预期动态身份已在本机记录
**When** 用户完成状态摘要核对、划除、归档查找与点击
**Then** 实际落页必须是该动态；作者主页或动态列表不算精确通过。

### 8.3 开播主闭环

**Given** 红魔 11 Pro+ 收到一条真实开播通知，预期直播间身份已在本机记录
**When** 用户划除通知后从 OMN 点击该条目
**Then** 实际页面必须对应同一直播间；若直播已结束，同一房间的结束页可通过身份核对，其他直播间不通过。

### 8.4 更新不制造重复

**Given** 同一真实 B 站通知在一个生命周期内多次更新
**When** 所有回调完成提交
**Then** 最终只有一个逻辑条目，`firstReceivedAt` 和排序位置不因更新改变，实际跳转使用最新受支持动作能力。

### 8.5 不同内容不误合并

**Given** 两条标题相同但预期内容身份不同的 B 站通知
**When** OMN 处理并显示它们
**Then** 形成两个可分别定位和跳转的条目，不因标题或正文相同被合并。

### 8.6 OMN 进程重建

**Given** 三类真实条目均已提交，原系统通知已划除
**When** OMN 进程被重建后逐条点击
**Then** 不访问旧运行时句柄；每类按持久目标实际落页或显示真实失效，且条目仍存在。

### 8.7 设备重启

**Given** 三类条目在重启前已提交
**When** 重启手机并重新进入 OMN
**Then** 三类记录、排序和动作能力状态按持久事实恢复；精确落页仅在实际身份一致时通过。

### 8.8 B 站强行停止

**Given** 已记录可识别动作层的 B 站条目
**When** 用户强行停止 B 站后从 OMN 点击
**Then** 记录取消、拒绝、错误页或成功的实际结果；任何失败都不删除条目，来源应用首页降级不计精确成功。

### 8.9 B 站更新

**Given** 更新前保存的投稿、动态和开播条目
**When** B 站客户端更新后逐条点击
**Then** 每条都记录实际落页；路由变化导致失败时显示分类原因，不因版本变化或条目年龄自动删除目标。

### 8.10 内容不可用

**Given** 精确身份对应内容已删除、下架、私密或不可访问
**When** 用户点击归档条目
**Then** 错误页或目标缺失被记录为失效边界，归档内容保持，且状态不得显示“已打开原内容”。

### 8.11 离线与未登录

**Given** 分别处于离线和退出登录状态
**When** 用户点击三类条目
**Then** OMN 的派发结果与 B 站加载/登录结果分别记录；网络或登录页不得被归因为 OMN 条目不存在。

### 8.12 来源应用卸载与重装

**Given** 三类条目及持久目标已存在
**When** 卸载 B 站后尝试跳转，再重装 B 站后重新尝试
**Then** 卸载期间显示 `NO_HANDLER` 且保留全部条目；重装后重新解析，不因之前失败或年龄拒绝尝试。

### 8.13 首页降级不算主闭环

**Given** 精确目标失败且用户明确选择“仅打开 B 站”
**When** B 站首页成功打开
**Then** 该失效处理可记为降级行为正确，但 `landingVerification` 不是精确通过，不能填补三类主闭环名额。

### 8.14 权限与渠道独立

**Given** 监听已连接
**When** 分别拒绝 `POST_NOTIFICATIONS`、关闭状态渠道和撤销通知使用权
**Then** 前两者只改变状态通知可见性，撤权改变未来采集；应用内三者状态和修复入口互不混淆。

### 8.15 断连补扫边界

**Given** 监听断连期间一条通知保持活动，另一条出现后已消失
**When** 监听重连并执行活动通知补扫
**Then** 活动通知只形成或恢复一个条目；已消失通知保持未观察，不得宣称找回或没有漏记。

## 9. 错误状态

| `AcceptanceReason` | 说明 | 对 A13 的影响 |
|---|---|---|
| `REAL_NOTIFICATION_NOT_OBSERVED` | 尚未取得所需真实推送。 | 对应三类主闭环阻断。 |
| `INGEST_NOT_OBSERVED` | 系统通知存在但 OMN 未观察回调。 | 失败，并关联监听证据。 |
| `COMMIT_FAILED` | 条目未原子提交。 | 失败，不得增加状态摘要计数。 |
| `DUPLICATE_ITEM` | 同一生命周期出现多个条目。 | 失败。 |
| `WRONG_MERGE` | 不同内容被合并。 | 失败。 |
| `ORDER_OR_GROUP_MISMATCH` | 列表/抽屉位置或内部顺序错误。 | 失败。 |
| `STATUS_SUMMARY_MISMATCH` | A10 摘要领先于提交、来源错误或锁屏泄露。 | 失败。 |
| `HEALTH_FACT_MISMATCH` | 五个健康维度与事实不一致。 | 失败。 |
| `EXACT_DISPATCH_FAILED` | 两层精确动作均失败。 | 主闭环失败；边界用例可验证降级。 |
| `WRONG_TARGET` | 落到首页、搜索、其他内容或其他直播间。 | 失败。 |
| `ERROR_PAGE` | 到达不存在、网络、登录或权限页。 | 主闭环失败；相应边界用例按真实分类。 |
| `LANDING_NOT_VERIFIED` | 只有派发结果，没有实际落页核对。 | `NOT_OBSERVED`，不得通过。 |
| `EVIDENCE_PRIVACY_VIOLATION` | 公开材料含真实通知或私密标识。 | 整批验收无效并停止公开材料流转。 |

## 10. 交互与人工核对流程

1. 测试前显示设备、构建、B 站版本、五个健康维度和待执行边界，不展示真实通知正文到公开录屏。
2. 收到通知后先在本机非跟踪记录预期内容身份，再等待 OMN 条目提交和 A10 摘要。
3. 主闭环必须由测试人员实际划除系统通知；测试夹具记录划除检查点，但不自动点击或取消来源通知。
4. 从 OMN 时间轴按正常用户路径定位条目；不得通过测试专用隐藏入口直达详情。
5. 点击后人工核对实际内容身份；公开报告只写别名和结果，不附含内容的截图。
6. 精确失败时按 A09 展示原因；只有边界用例需要时才点击“仅打开来源应用”。
7. 每个用例结束时显示检查点缺口；缺证据只能选择 `NOT_OBSERVED` 或重跑，不提供“按预期通过”。

全部按钮和条目满足 48dp、TalkBack 语义、最大字体、横竖屏和分屏操作要求。用例状态不得只靠颜色表达。

## 11. 隐私与性能约束

- OMN 核心功能和验收记录器默认无网络、无遥测、无远程心跳；B 站自身访问网络不属于 OMN 网络流量，测试报告必须区分。
- 真实通知、目标身份、动作和截图仅可在本机非 Git 跟踪位置按测试需要短期保存；公开摘要使用非可逆别名。
- release 构建不得为了 A13 保留详细正文日志、可写调试 Provider、自动截屏、远程上报或测试后门。
- 验收埋点只记录既有领域事件和去敏枚举，不得新增轮询、唤醒锁、精确闹钟、高频心跳或常驻测试服务。
- A13 执行期间的新通知仍走生产摄取链路；证据收集不得阻塞回调或数据库事务。
- 三类闭环和边界回归同时记录后台 PSS、CPU、唤醒、写盘、数据库增长和状态通知刷新；绝对预算由 A14/`SP-09` 锁定，任一同场景未解释回退超过 10% 阻断版本。

## 12. 测试要求

### 12.1 自动化与可控集成测试

- 用生成通知夹具覆盖检查点状态机、缺失证据、无效用例、结果聚合和三类主闭环门；夹具不能替代真机主闭环。
- 用去隐私化投稿/动态/开播字段快照覆盖 `SP-01` 已确认的缺字段、更新、移除、key 复用和同标题不同目标反例。
- 集成测试覆盖 A03—A09 的提交、唯一条目、稳定排序、抽屉、进程重建后持久目标和三层跳转结果。
- UI 自动化覆盖划除后的归档定位、抽屉展开、失败原因、显式降级、TalkBack 和最大字体。
- 结果聚合性质测试证明：任一类型没有 `PRIMARY_DISMISSED_FLOW PASS` 时总结果必为失败；降级不能改变该结论。
- 敏感信息哨兵扫描覆盖报告、日志、异常、测试附件索引和诊断导出。

### 12.2 红魔 11 Pro+ 阻断性真机测试

- 三类真实通知各至少一次 `PRIMARY_DISMISSED_FLOW PASS`，并完成 6.2 节全部适用边界。
- 所有用例使用 release 或记录差异的 release measurement 构建；debug、模拟器或其他手机结果不计入阻断门。
- 覆盖 B 站普通进程结束、强行停止、更新、退出登录、离线、卸载/重装，OMN 进程重建、设备重启、通知使用权撤销、监听重连、`POST_NOTIFICATIONS` 和渠道关闭。
- 覆盖原通知仍在、划除后、`SP-02` 锁定的全部等待检查点、运行时动作取消及一次性动作适用场景。
- 覆盖内容删除/下架/权限变化的三种目标结构；使用经验证失效目标时在报告中标记它不替代真实主闭环。
- 每个失败必须保留去敏枚举、步骤和影响；不得删除失败用例后只汇报成功样本。

## 13. Phase 0 Spike 与决策门

### 13.1 Spike 输入

- `SP-01` 锁定三类真实通知字段、系统身份、更新/移除序列和反例。
- `SP-02` 锁定运行时动作在划除、等待、进程/来源状态变化下的寿命、一次性语义和持有成本。
- `SP-03` 为三类分别给出“精确持久目标”“仅当前进程精确动作”或“不支持”，并验证重启后的实际落页。
- `SP-04` 证明突发、更新、事务中止和补扫不会漏记、重复或破坏唯一条目。
- `SP-05` 锁定红魔授权、断连、重连、长锁屏、系统回收和重启边界。
- `SP-06` 选择唯一生产状态通知拓扑；FGS 若未通过合法性与 A/B 资源门，保持不采用。

### 13.2 Phase 0 分类门

每种 B 站类型必须在 Phase 0 能被分类，不能留成无含义的“可能支持”：

| 分类 | 可进入 v0.4 主闭环吗 |
|---|---:|
| 跨进程/重启的精确持久目标，实际落页已验证 | 是。 |
| 仅当前进程运行时精确动作 | 只能进入受限实验；若不能覆盖用户实际查看周期，A13 不通过。 |
| 只能 `APP_LAUNCH`、首页或搜索 | 否。 |
| 尚未取得真实通知或落页 | 否，状态为 `NOT_OBSERVED`。 |

### 13.3 `v0.4` 总决策门

- **GO**：投稿、动态、开播三类各至少一个主闭环精确通过；全部适用失效边界有可复现结果；A01—A12 无阻断回归；release 真机满足 A14 预算和 10% 门；公开证据通过敏感扫描。
- **REDIRECT**：某类只能在更窄生命周期或特定用户设置下精确跳转，但仍可能满足重新定义后的产品；先更新计划、A09、本规格和用户文案并由用户确认。
- **STOP**：任一必需类型只能打开首页/搜索、依赖私有 API或不受支持的动作持久化，或完整正确路径只能靠不合规 FGS、高频唤醒、轮询或违反绝对预算的方案。

A13 只有在 `GO` 证据齐全时才能标记完成。真实通知等待、未验证落页、仅派发成功、仅首页降级或任一必需边界被省略，都不能用“基本可用”替代完成声明。
