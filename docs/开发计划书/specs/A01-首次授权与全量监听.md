# A01 首次授权与全量监听规格说明

- **主交付版本**：`v0.1`
- **优先级**：`[A]`
- **规格状态**：`[已确认] plan-v1.0 基线；Phase 0 未决项保持待验证`
- **Phase 0 依赖**：`SP-05 监听可靠性与红魔后台策略`、`SP-06 状态通知与前台服务 A/B`、`SP-09 持久化、隐私与性能基线`
- **功能依赖**：Android 16 通知使用权设置、`NotificationListenerAdapter`、`HealthEvidenceRepository`、A08 本地持久化
- **被依赖**：A03 通知事件采集、A10 常驻状态通知、A11 健康状态时间轴、A13 B 站端到端真机验收

## 1. 目标与范围

本功能负责让用户理解并完成 OMN 的首次系统授权，在应用内持续展示彼此独立的五个事实维度，并在系统确实连接 `NotificationListenerService` 后启动默认全量监听：

1. 通知使用权；
2. `POST_NOTIFICATIONS` 状态通知显示权限；
3. “运行状态”通知渠道；
4. 通知监听连接；
5. 当前进程会话证据。

`[已确认]` “全量监听”指 Android 系统实际交付给 OMN、且未被自动排除或用户排除的通知。它不包含系统未向监听器公开的通知，也不承诺断连期间出现并消失的通知可被补回。

`[已确认]` 通知使用权是核心采集前提；`POST_NOTIFICATIONS` 只控制应用外状态通知是否可见，不控制 `NotificationListenerService` 是否有权接收通知。状态通知渠道、监听连接和进程证据也不得与上述任一权限合并成一个“总开关”。

### 1.1 本功能不做

- 不让用户在首次授权时选择“只监听 B 站”；默认监听全部系统可见且未排除的来源。
- 不实现应用排除列表；A02 负责用户排除，本应用包名在本功能中始终自动排除。
- 不把通知使用权已授予写成“监听一定在线”。
- 不把 OMN 进程当前存在写成“通知监听一定已连接”。
- 不把状态通知可见写成进程实时存活证明。
- 不通过轮询、高频重绑、唤醒锁、精确闹钟或常驻循环等待权限或连接变化。

## 2. 术语与公共状态契约

以下状态名是 A01、A10、A11 共用的跨功能契约；实现不得为同一事实另造含义不同的布尔值。

| 术语/类型 | 值 | 精确定义 |
|---|---|---|
| `ListenerAccessState` | `GRANTED` | 系统当前报告 OMN 已获得通知使用权。只说明授权，不说明监听已连接。 |
|  | `NOT_GRANTED` | 系统当前报告未授权或授权已被撤销。 |
|  | `UNKNOWN` | 系统状态读取失败或尚无可用结果；不得按已授权处理。 |
| `StatusPermissionState` | `NOT_REQUESTED` | OMN 尚未向用户请求 `POST_NOTIFICATIONS`，或本地没有请求记录。 |
|  | `GRANTED` | 系统当前允许 OMN 显示通知。 |
|  | `DENIED` | 系统当前拒绝 OMN 显示通知。它不改变通知使用权。 |
|  | `UNKNOWN` | 权限读取失败；不得按已允许处理。 |
| `StatusChannelState` | `NOT_CREATED` | A10 尚未创建固定“运行状态”渠道。 |
|  | `ENABLED` | 渠道已创建且系统报告可发布。 |
|  | `DISABLED` | 渠道已创建但被用户或系统关闭。 |
|  | `UNKNOWN` | 渠道状态无法读取；不得按可见处理。 |
| `ListenerConnectionState` | `NEVER_OBSERVED` | 当前进程会话尚未收到连接或断连回调。 |
|  | `CONNECTED` | 当前进程会话最后一个监听连接事实是 `LISTENER_CONNECTED`，且之后没有同连接的断连事实。 |
|  | `DISCONNECTED` | 当前进程会话最后一个监听连接事实是 `LISTENER_DISCONNECTED`，或连接已明确失效。 |
| `ProcessEvidenceState` | `CURRENT_SESSION_ACTIVE` | 当前运行进程拥有本次启动生成的 `runtimeSessionId`；它只证明当前代码正在执行。 |
|  | `NO_CURRENT_SESSION_EVIDENCE` | 查询历史时没有可验证的当前进程会话；不等于已知的精确停止时刻。 |
| `StatusVisibilityWarning` | `PERMISSION_NOT_REQUESTED`、`PERMISSION_DENIED`、`CHANNEL_NOT_CREATED`、`CHANNEL_DISABLED`、`STATE_UNKNOWN` | 只描述状态通知可见性问题；不得改变核心监听 readiness。 |
| `CoreListeningReadiness` | `ACCESS_REQUIRED` | `listenerAccessState=NOT_GRANTED`。 |
|  | `AWAITING_CONNECTION` | 使用权已授予，但当前会话尚未观察到监听连接。 |
|  | `LISTENING` | 使用权已授予且当前会话监听连接为 `CONNECTED`。 |
|  | `INTERRUPTED` | 使用权仍授予，但当前会话已观察到 `DISCONNECTED`。 |
|  | `CHECK_FAILED` | 使用权或必要系统状态为 `UNKNOWN`。 |

## 3. 用户故事

> 作为首次安装 OMN 的用户，我想清楚地知道哪些系统能力用于记录通知、哪些只用于显示运行状态，并在授予通知使用权后看到真实监听连接结果，以便确认应用已经具备记录系统交付通知的条件。

> 作为已经使用 OMN 的用户，我想在权限被撤销或监听断开后看到准确原因和修复入口，以便不会在应用实际无法确认记录时仍误以为一切正常。

## 4. 输入契约

### 4.1 `AuthorizationSnapshot`

| 字段 | 逻辑类型 | 必填 | 来源 | 约束 |
|---|---|---:|---|---|
| `observedAt` | `InstantUtc` | 是 | 系统状态读取时钟 | UTC；同一快照所有权限事实使用同一观察批次。 |
| `runtimeSessionId` | `RuntimeSessionId` | 是 | 应用进程启动 | 每次进程启动生成新值，不跨进程复用。 |
| `listenerAccessState` | `ListenerAccessState` | 是 | Android 通知使用权状态 | 不能从监听连接反推。 |
| `statusPermissionState` | `StatusPermissionState` | 是 | Android 运行时通知权限 | 不能从状态通知是否存在反推。 |
| `statusChannelState` | `StatusChannelState` | 是 | Android 通知渠道 | A10 交付前允许为 `NOT_CREATED`。 |
| `listenerConnectionState` | `ListenerConnectionState` | 是 | 当前会话监听生命周期 | 只能由真实连接/断连回调更新。 |
| `processEvidenceState` | `ProcessEvidenceState` | 是 | 当前进程内存状态 | 首次授权界面运行时应为 `CURRENT_SESSION_ACTIVE`。 |
| `statusFeatureAvailable` | `Boolean` | 是 | 版本能力配置 | `false` 时不得提前请求仅供 A10 使用的权限；仍分项显示其状态与用途。 |

### 4.2 `AuthorizationIntent`

| 变体 | 载荷 | 必填 | 行为 |
|---|---|---:|---|
| `OPEN_LISTENER_ACCESS_SETTINGS` | 无 | 是 | 打开系统通知使用权设置；OMN 不能直接授予该特殊访问权。 |
| `REQUEST_STATUS_PERMISSION` | 无 | 是 | 仅当 `statusFeatureAvailable=true` 且状态为 `NOT_REQUESTED` 或 `DENIED` 时触发系统权限请求。 |
| `OPEN_APP_NOTIFICATION_SETTINGS` | 无 | 是 | 权限被拒绝且系统不再展示直接请求时，进入 OMN 通知设置。 |
| `OPEN_STATUS_CHANNEL_SETTINGS` | `channelId: String` | 是 | 仅当渠道已创建时打开固定“运行状态”渠道设置。 |
| `REFRESH_SYSTEM_STATE` | 无 | 是 | 由用户点击或 Activity 恢复触发一次状态读取；不得形成周期刷新。 |
| `OPEN_INBOX` | 无 | 是 | 所有状态均可进入以查看既有记录；监听异常作为持续可见横幅，不锁住历史数据。 |

## 5. 输出契约

### 5.1 `AuthorizationUiState`

| 字段 | 逻辑类型 | 必填 | 说明 |
|---|---|---:|---|
| `coreReadiness` | `CoreListeningReadiness` | 是 | 仅由通知使用权和监听连接组合，计算规则见第 6 节。 |
| `listenerAccessState` | `ListenerAccessState` | 是 | 原样呈现当前系统事实。 |
| `statusPermissionState` | `StatusPermissionState` | 是 | 与监听状态分卡显示。 |
| `statusChannelState` | `StatusChannelState` | 是 | 与权限、监听状态分卡显示。 |
| `listenerConnectionState` | `ListenerConnectionState` | 是 | 显示“已连接”“等待连接”或“连接中断”，不用“权限正常”替代。 |
| `processEvidenceState` | `ProcessEvidenceState` | 是 | 显示“当前会话已观察”，不得显示“永远运行”。 |
| `lastObservedAt` | `InstantUtc` | 是 | 界面按设备时区显示，诊断使用 UTC。 |
| `primaryAction` | `AuthorizationIntent?` | 否 | 当前最直接修复动作；没有动作时为空。 |
| `canCompleteOnboarding` | `Boolean` | 是 | 仅当 `coreReadiness=LISTENING` 时为 `true`；表示首次核心授权流程完成。 |
| `canOpenInbox` | `Boolean` | 是 | 固定为 `true`；权限或连接异常不能阻止查看既有本地记录。 |
| `statusVisibilityWarnings` | `Set<StatusVisibilityWarning>` | 是 | 可为空；同时存在多个问题时全部保留，不改变 `coreReadiness` 或 `canOpenInbox`。 |

### 5.2 事实输出

| 输出 | 逻辑类型 | 产生条件 | 约束 |
|---|---|---|---|
| 进程启动事实 | `HealthEvidence(PROCESS_STARTED)` | 每次进程启动一次 | 不等于监听连接。 |
| 监听连接事实 | `HealthEvidence(LISTENER_CONNECTED)` | 系统连接回调 | 带当前 `runtimeSessionId` 和新 `listenerConnectionId`。 |
| 监听断连事实 | `HealthEvidence(LISTENER_DISCONNECTED)` | 系统断连回调 | 结束当前连接；不得虚构断连前漏记数量。 |
| 通知使用权观察 | `HealthEvidence(ACCESS_OBSERVED)` | 首次读取、Activity 恢复、用户刷新、状态变化处理 | 值为 `GRANTED`、`NOT_GRANTED` 或 `UNKNOWN`。 |
| 状态通知权限观察 | `HealthEvidence(STATUS_PERMISSION_OBSERVED)` | 同上 | 与通知使用权分开。 |
| 渠道状态观察 | `HealthEvidence(STATUS_CHANNEL_OBSERVED)` | 渠道存在后读取 | A10 交付前为 `NOT_CREATED`，不写成错误。 |

所有事实只保存枚举、时间、会话/连接 ID 和必要诊断，不保存通知正文或动作。

## 6. 状态机与判定规则

### 6.1 核心监听状态机

```text
首次进入
  ├─ 使用权 NOT_GRANTED ──> ACCESS_REQUIRED
  │      └─ 用户打开系统设置并返回 ──> 重新读取
  ├─ 使用权 UNKNOWN ──────> CHECK_FAILED
  └─ 使用权 GRANTED
         ├─ 尚无连接回调 ──> AWAITING_CONNECTION
         ├─ CONNECTED ─────> LISTENING
         └─ DISCONNECTED ──> INTERRUPTED

LISTENING
  ├─ 使用权撤销 ──────────> ACCESS_REQUIRED
  ├─ 系统断连 ────────────> INTERRUPTED
  └─ 进程重建 ────────────> 新会话的 AWAITING_CONNECTION，等待新连接事实
```

精确判定顺序：

1. `listenerAccessState=UNKNOWN` 时输出 `CHECK_FAILED`。
2. `listenerAccessState=NOT_GRANTED` 时输出 `ACCESS_REQUIRED`，无视旧连接历史。
3. 使用权为 `GRANTED` 且连接为 `NEVER_OBSERVED` 时输出 `AWAITING_CONNECTION`。
4. 使用权为 `GRANTED` 且连接为 `DISCONNECTED` 时输出 `INTERRUPTED`。
5. 只有使用权为 `GRANTED` 且当前会话连接为 `CONNECTED` 时输出 `LISTENING`。
6. `POST_NOTIFICATIONS`、渠道和进程证据不得改变上述五步结果；它们独立形成状态通知可见性和证据说明。

### 6.2 首次授权流程规则

1. 首次界面先解释通知使用权允许读取系统交付通知，再提供系统设置入口；不得用自制开关假装已经授权。
2. 用户从系统设置返回时，Activity `onResume` 触发一次状态读取；如果仍未授权，保留在 `ACCESS_REQUIRED`，不循环弹出设置页。
3. 授权后等待真实 `onListenerConnected`。在回调到达前显示“已授权，等待监听连接”，不显示“正在记录”。
4. `statusFeatureAvailable=false` 时，不请求 `POST_NOTIFICATIONS`；界面仍说明它与监听无关、将在 A10 启用状态卡时使用。
5. `statusFeatureAvailable=true` 时，通知权限请求必须紧邻“显示运行状态通知”的解释和用户动作；拒绝后允许继续使用核心收件箱。
6. 状态渠道由 A10 以固定 ID 创建；A01 不通过删除重建渠道覆盖用户设置。
7. 默认监控策略为“除 OMN 自身及 A02 用户排除项外全部接纳”。查看筛选不参与本状态机。

## 7. 权限与生命周期边界

- **权限撤销**：应用前台恢复或收到相关生命周期机会时重新读取；发现撤销后立即停止显示 `LISTENING`。OMN 无法在进程完全未运行时自行观察撤销时刻，因此历史空档由 A11 标为未确认。
- **连接先于界面**：若监听已在后台连接，界面首次收集状态时直接显示当前会话 `CONNECTED`；不要求用户重复授权。
- **进程重建**：旧会话的 `CONNECTED` 不可带入新会话。新 `runtimeSessionId` 初始连接状态为 `NEVER_OBSERVED`，等待系统回调。
- **系统断连**：记录断连事实并输出 `INTERRUPTED`。是否以及如何调用平台重绑能力由 `SP-05` 锁定；禁止无界重绑循环。
- **设备重启**：不得仅凭持久权限值显示 `LISTENING`；必须在新进程/新连接收到正面事实。
- **并发状态变化**：同一 UI 快照按 `observedAt` 与稳定序列只接受较新的状态。连接回调和 Activity 权限刷新互不覆盖对方维度。
- **无网络**：授权、监听和状态读取完全离线工作；网络状态不改变核心监听 readiness。
- **多用户/工作资料**：全量监听范围以系统实际交付为准；后续通知身份必须保留 `sourceUser`，不能只按包名归并。

## 8. Given / When / Then 验收条件

1. **首次未授权**<br>
   Given 全新安装且通知使用权未授予，When 用户打开 OMN，Then 页面显示 `ACCESS_REQUIRED`、解释用途并提供系统设置入口，不显示“正在记录”。

2. **授权后等待连接**<br>
   Given 用户在系统设置授予通知使用权，When 返回 OMN 但系统尚未回调连接，Then 页面显示 `AWAITING_CONNECTION`，且 `canCompleteOnboarding=false`、`canOpenInbox=true`。

3. **真实连接后就绪**<br>
   Given 使用权为 `GRANTED`，When 当前会话收到 `onListenerConnected`，Then 生成连接事实并显示 `LISTENING`，`canCompleteOnboarding=true`；收件箱入口在此前后都可用。

4. **通知权限独立**<br>
   Given 通知使用权已授予且监听已连接、`POST_NOTIFICATIONS` 被拒绝，When 用户查看授权状态，Then 核心状态仍为 `LISTENING`，同时独立提示“运行状态通知不可见”。

5. **渠道独立**<br>
   Given 监听已连接且状态通知权限已授予、运行状态渠道被关闭，When 应用读取状态，Then 监听仍显示 `LISTENING`，渠道显示 `DISABLED` 并提供渠道设置入口。

6. **授权撤销**<br>
   Given 当前为 `LISTENING`，When 用户撤销通知使用权并返回 OMN，Then 状态变为 `ACCESS_REQUIRED`，保留历史数据，不再声称正在记录。

7. **监听断连**<br>
   Given 使用权仍为 `GRANTED`，When 系统发出监听断连回调，Then 状态变为 `INTERRUPTED`，记录断连事实，不把断连解释成通知权限被拒绝。

8. **进程重建**<br>
   Given 上一会话曾连接，When OMN 进程重建但尚无新连接回调，Then 新会话状态为 `AWAITING_CONNECTION` 而非沿用旧 `LISTENING`。

9. **自我排除**<br>
   Given OMN 发布自己的状态通知，When 系统把该通知回调给监听器，Then 在复制标题、正文和动作前以包名自动排除，不产生通知条目或正文诊断。

10. **系统状态读取失败**<br>
    Given 权限状态读取抛错或返回不可判定结果，When 页面组合状态，Then 输出 `CHECK_FAILED` 和一次性重试入口，不按已授权继续。

11. **拒绝循环打扰**<br>
    Given 用户从通知使用权设置返回且仍未授权，When 页面恢复，Then 只刷新并显示 `ACCESS_REQUIRED`，不自动再次跳转设置或反复弹窗。

12. **离线授权**<br>
    Given 设备无网络，When 用户授予通知使用权并收到连接回调，Then 状态正常进入 `LISTENING`，不发起网络请求。

## 9. 错误状态

| 错误状态 | 触发条件 | 用户看到什么 | 系统行为 |
|---|---|---|---|
| `ACCESS_NOT_GRANTED` | 通知使用权未授予/已撤销 | “尚未获得通知使用权”及设置入口 | 不宣称记录；保留历史数据。 |
| `ACCESS_CHECK_FAILED` | 特殊访问状态读取失败 | “无法确认通知使用权”及手动重试 | 记录无正文错误枚举；不按已授权处理。 |
| `WAITING_FOR_CONNECTION` | 已授权但本会话无连接事实 | “已授权，等待系统连接监听” | 等待真实回调；不轮询。 |
| `LISTENER_INTERRUPTED` | 已观察到断连 | “监听连接已中断”及 Phase 0 锁定的恢复动作 | 记录断连证据；不虚构漏记数量。 |
| `STATUS_PERMISSION_DENIED` | `POST_NOTIFICATIONS=DENIED` | “运行状态通知不可见”及设置入口 | 核心监听继续独立判断。 |
| `STATUS_CHANNEL_DISABLED` | 渠道被关闭 | “运行状态渠道已关闭”及渠道入口 | 不删除重建渠道规避用户选择。 |
| `SETTINGS_INTENT_UNAVAILABLE` | 系统设置入口无法解析 | “无法打开系统设置，请在设置中手动进入” | 不崩溃；记录系统版本与错误枚举。 |
| `STATE_PERSIST_FAILED` | 健康事实写入失败 | “状态记录异常；当前显示仅供本次会话参考” | 当前内存状态仍可显示，但不得把未持久化事实用于历史蓝区间。 |

## 10. 交互与无障碍

首次授权页按固定顺序展示：

1. 通知使用权卡：用途、当前状态、系统设置按钮；
2. 监听连接卡：当前会话连接状态与最近观察时间；
3. 运行状态通知卡：`POST_NOTIFICATIONS` 和渠道两个独立子状态；
4. 当前会话说明：明确“进程已打开”不等于“监听已连接”；
5. 完成首次设置按钮：仅在 `LISTENING` 时启用；“查看既有记录”入口在所有状态可用，进入后保留异常横幅。

所有按钮有效触控范围至少 48dp。状态同时使用图标、文字和 TalkBack 描述，不只用颜色。最大字体、横竖屏、分屏和 edge-to-edge 下必须能完成全部授权与设置跳转。系统设置返回后焦点回到触发该动作的状态卡。

## 11. 隐私与性能约束

- 权限和健康事实只保存枚举、UTC 时间、会话/连接 ID 与必要错误分类，不保存通知正文、动作或完整系统设置返回对象。
- A01 不申请网络、联系人、短信、存储或无障碍权限。
- 权限刷新只在首次显示、Activity 恢复、用户点击刷新或真实生命周期变化时执行；不得使用后台定时器。
- 监听等待与恢复不得持有唤醒锁、使用精确闹钟、短周期 `WorkManager` 或空转前台服务。
- 状态变化只写入发生变化的健康事实；重复读取到同一事实是否压缩及其诊断边界由 Phase 0 锁定，但不能用压缩丢掉授权撤销或连接中断。
- release 真机 8 小时息屏无通知测试必须证明本功能没有主动周期唤醒或数据库写入。

## 12. 测试要求

### 12.1 自动化测试

- `CoreListeningReadiness` 五态判定表，覆盖每个权限/连接组合及 `UNKNOWN` 优先级。
- `POST_NOTIFICATIONS`、渠道、连接和进程证据不会改变彼此状态的独立性测试。
- 新 `runtimeSessionId` 不继承旧会话 `CONNECTED` 的状态恢复测试。
- 较旧状态快照不能覆盖较新快照的顺序测试。
- 自包名在内容复制前排除的适配器测试。
- 设置入口不可解析、状态读取异常和事实持久化失败的错误映射测试。
- Compose 语义测试：按钮启用条件、状态文案、焦点顺序、48dp 触控目标和最大字体。

### 12.2 红魔 11 Pro+ 真机测试

- 全新安装、拒绝授权、授予授权、撤销后恢复。

## 13. Phase 0 Spike 与决策门

### 13.1 必须回答的问题

1. 红魔 11 Pro+ 上首次授权后监听连接何时出现，进程重建、系统回收和重启后如何恢复？
2. 断连后平台是否自动重连；若需主动请求重绑，合法触发点、次数上限和资源成本是什么？
3. 活动通知补扫能覆盖什么、不能覆盖什么，是否制造重复？
4. `POST_NOTIFICATIONS` 被拒绝、渠道关闭时，对监听连接和候选前台服务分别有什么影响？
5. 哪些红魔后台设置是必要条件，哪些只是观察变量？

### 13.2 证据产物

- 脱敏监听生命周期序列：会话 ID、连接 ID、事件枚举、UTC 时间和系统状态；
- 授权/撤权/断连/重连/进程重建/重启矩阵；
- 可复现系统设置路径和厂商设置记录；
- release 构建 8 小时息屏结果；
- 不可观测漏记窗口和用户可见文案清单。

### 13.3 决策门

- **GO**：授权、连接和恢复路径可复现；UI 能区分五个维度；无主动轮询或周期唤醒；已知不可观测窗口被诚实呈现。
- **REDIRECT**：需要用户配置额外厂商设置、需要有界重绑策略或补扫边界改变产品承诺；先回写计划并由用户确认。
- **STOP**：在合规、低闲置成本的方案下无法获得可用通知监听，或只能靠高频唤醒/不合规后台机制维持核心能力。

A01 只有在 Phase 0 得出 `GO`，并且本节证据与自动化/真机验收全部可追溯时，才可在 `v0.1` 标记完成。
