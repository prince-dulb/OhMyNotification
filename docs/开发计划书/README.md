## 已确认方向

- 应用名“救救我的通知！”，英文名 “Oh My Notification!”；包名 `io.github.prince_dulb.ohmynotification`。
- 原生 Kotlin + Jetpack Compose + Material 3 + Room，Android 16 首发，不使用 Flutter。
- 红魔 11 Pro+（16GB + 1TB、Android 16、不支持 32 位应用）是首要阻断设备。
- 默认监控系统交付给 OMN 的全部通知，自动排除自身；用户排除与查看筛选是两套独立状态。
- 默认列表严格按首次接收时间倒序；短时间同应用通知按固定 15 分钟/跨 3 条规则形成确定性抽屉。
- 不提供已读/未读；长期通知条目 v0 不自动删除。
- 跳转没有人为年龄期限，但动作是否仍有效由 Android/来源应用实际结果决定。
- 本地优先、无遥测、无远程心跳；空闲事件驱动，性能占用是硬门。
- GPL-3.0-or-later 全部开源；许可正文见 [LICENSE](../../LICENSE)。
- v0 不预埋通用常驻后台宿主；出现第二个真实后台需求后再按架构扩展边界设计。

## Phase 0 尚待事实

- B 站投稿、动态、开播各自能否提取跨进程/重启的精确持久目标。
- 原始 `PendingIntent` 在划除、等待、来源 stopped/更新和句柄数量增长下的寿命与成本。
- 红魔通知监听在长锁屏、回收、强停、重连和重启时的真实可靠性边界。
- 普通 ongoing 状态通知与合法 FGS 候选中哪一个能诚实满足状态语义且资源更低。
- 哪些自然事实足以生成蓝色已确认区间，黄色比例是否可接受。
- Android 包可见性下排除设置来源目录是否足够完整；是否有必要提出 `QUERY_ALL_PACKAGES`。
- 生产 Room schema/索引、队列/批量、诊断/缓存/导出上限和绝对性能预算。
