# 详细开发计划变更记录

本文件记录计划事实、范围和决策的变化。实现提交、测试 run 和发布说明应引用相应版本文档，不在这里伪造为计划进度。

## 未发布：`plan-v1.0` 候选（2026-08-22）

### 新增

- 为 A01—A14、B01—B03 建立 17 份独立功能规格。
- 建立 Phase 0 到 `v0.5` 的版本路线图，全部功能各有唯一主交付版本。
- 建立单 `:app` 候选架构、通知摄取/归并/持久化链路、动作双轨、健康证据与确定性时间抽屉模型。
- 建立可测量的非功能需求、T0—T6 测试策略、九个 Spike 协议和分阶段任务表。
- B03 采用“两阶段导出”：先在应用私有空间生成并通过字段白名单/敏感扫描，再请求用户选择外部保存位置。
- A02 增加来源目录覆盖度模型，明确 Android 包可见性限制不得伪装成完整列表。

### 对齐

- 跳转不设置记录年龄 TTL；运行时 `PendingIntent` 不持久化，持久精确目标与应用入口降级严格区分。
- 默认顺序锁定为 `firstReceivedAt DESC, ingestSequence DESC, itemId DESC`。
- 时间抽屉锁定为 15 分钟、最多跨 3 条其他来源、最少 2 条、锚点式非重叠算法。
- 通知使用权、`POST_NOTIFICATIONS`、状态渠道、监听连接和进程证据保持五维独立。
- 蓝色只表示有正面监听证据的 `CONFIRMED_RUNNING`，黄色表示 `UNCONFIRMED`，不虚构停机时刻。
- 常驻状态通知只消费已提交事实；普通 ongoing 与 FGS 在 Phase 0 A/B 后二选一。
- 低资源门覆盖 8 小时息屏、100 条突发、10,000 条历史、数据库增长和 10% 回归。
- v0 长期通知条目不自动删除；诊断与缓存有界值待 Phase 0 锁定。
