# P0-107 / SP-07 健康证据与区间精度

状态：`[候选] LOGIC_GO / REDMAGIC_BLIND_RECONCILIATION_NOT_RUN`

验收时间：2026-08-23（Asia/Shanghai）

## 1. 范围与结论边界

本 Spike 已用纯 Kotlin 参考模型验证 A11 的保守区间推导：只有同一监听连接的正面证据之间、正面证据到明确断连边界之间，或当前仍连接时最后一条正面证据到本次观察时刻之间可以标为蓝色“已确认运行”；其余时间一律为黄色“未确认运行”。

该结果证明领域规则能够生成完整、无重叠且不凭空延长的蓝黄区间。它尚未完成 P0-105 提供的红魔真实生命周期时间线、已知动作盲对账、黄色比例和 8 小时零额外唤醒测量，因此不能锁定生产正面证据集合，也不能宣称 P0-107 整体完成。

## 2. 固定数据与候选规则


当前候选正面证据：

- `LISTENER_CONNECTED`；
- `NOTIFICATION_CALLBACK`；
- `RECOVERY_COMPLETED`。

生产候选将成功创建的新逻辑条目映射为 `NOTIFICATION_COMMITTED`，将移除映射为 `NOTIFICATION_REMOVED`；同一生命周期的连续正文更新仍完整更新通知条目，但只有当前监听连接距上一条正面证据至少 5 分钟时才追加健康事实。窗口只由真实事件触发，不安排心跳；因此不会为画蓝线额外唤醒，同时把持续进度通知造成的健康表写放大限制在每连接每 5 分钟至多一条更新证据。没有证据覆盖的历史段继续按黄色解释，不能用节流后的稀疏事实外推永久存活。

当前明确边界：

- 对应连接的 `LISTENER_DISCONNECTED`；
- 全局 `ACCESS_NOT_GRANTED`。

`PROCESS_STARTED`、通知使用权、状态通知权限和状态通知渠道只形成各自状态事实，单独出现时不得生成蓝段。状态通知是否可见也不缩短已经成立的监听证据区间。

## 3. 区间语义

时间轴只包含两种状态：

| 状态 | 含义 | 禁止解释 |
|---|---|---|
| `CONFIRMED_RUNNING` | 有监听连接正面证据支持的时间范围 | 不等于进程永久存活，也不保证期间每条系统通知都已送达 |
| `UNCONFIRMED` | 缺少足够正面证据 | 不等于已停机或已经漏记 |

实时投影只允许在查询时内存状态仍为同一 `runtimeSessionId + connectionId + CONNECTED` 时，从最后正面证据延伸到 `observedNow`。旧进程突然终止、连接身份跨会话复用或壁钟回拨都不会投影蓝段。

推导结果同时输出五个相互独立的状态面：进程、监听连接、通知使用权、状态通知权限、状态通知渠道。后续 UI 必须分别呈现修复入口，不能用一条“应用在运行”覆盖所有故障。

## 4. 自动化覆盖

纯 JVM 参考实现与测试位于 `app/src/test/.../phase0/sp07/`，不进入 APK。覆盖：

1. 当前连接只从最后正面证据投影到本次观察时刻；
2. 相邻正面证据之间形成蓝段；
3. 明确断连结束蓝段；
4. 旧进程突然终止后的区间保持黄色；
5. 进程与权限事实单独出现不生成蓝段；
6. 状态通知权限、渠道与监听状态相互独立；
7. 通知使用权撤销结束当前蓝段；
8. 同一 UTC 时刻使用证据序列稳定破平局；
9. 跨会话复用连接 ID 时保守拒绝蓝段；
10. 壁钟回拨产生诊断并拒绝该会话的全部蓝段；
11. 固定种子 1,000 轮随机输入始终生成完整、无空洞、无重叠区间；
12. 固定数据的 SHA-256、隐私哨兵、五状态面和零周期唤醒合同。

## 5. 性能边界

参考模型没有轮询、心跳、闹钟、唤醒锁或后台循环；查询仅在已有证据与明确的 `observedNow` 上执行。数据集把 `periodicWakeups=0` 固定为结构合同。

这只能证明当前算法不需要周期唤醒，不能证明 Android 实现和红魔 ROM 在 8 小时息屏期间实际为零唤醒。生产实现仍需限制诊断事实规模，并在 P0-109 使用 release 构建测量 CPU、PSS、唤醒和写盘。

## 6. 决策与待验证项

`SP-07 LOGIC_GO`：采用“正面监听证据只确认有限区间、其余诚实显示黄色”的领域规则作为生产实现候选；五个健康状态面保持独立，不用常驻状态通知替代监听证据。

以下项目完成前，P0-107 保持 `DEVICE_PRECISION_NOT_RUN`：

- P0-105 的长锁屏、系统回收、强停、重连、重启和权限切换时间线；
- 用外部已知动作时间与派生区间进行盲对账，检查是否存在虚假蓝段；
- 统计典型使用与 8 小时息屏中的黄色比例，判断证据是否过度保守；
- 确认 `RECOVERY_COMPLETED` 在真实回调顺序中是否足以作为正面证据；
- 使用单调时钟辅助跨壁钟变化的可显示区间，而不错误延长蓝段；
- 验证 Android 实现不为时间轴新增周期工作、唤醒锁、精确闹钟或状态通知刷新。
