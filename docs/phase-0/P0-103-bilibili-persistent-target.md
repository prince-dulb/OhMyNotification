# P0-103 / SP-03 B 站持久精确目标

状态：`[候选] NO_PERSISTENT_TARGET_IN_OBSERVED_FIELDS / RUNTIME_ACTION_AVAILABLE`

建立时间：2026-08-23（Asia/Shanghai）

## 1. 目的与边界

本 Spike 判断 B 站通知中是否存在可跨 OMN 进程重建和设备重启保存的精确 URI、BV/AV 号或其他结构化内容目标。它不尝试反射、解包、序列化或持久化 `PendingIntent`，也不把标题搜索、来源包名或系统通知 key 冒充内容目标。

原始通知正文、字段值、系统 key、URI 和内容 ID 只允许进入 `.local-evidence/`。本文只记录字段存在性、语法分类和计数。

## 2. 已观察 B 站样本

当前私有事件流包含 91 条 B 站回调，对应 31 个唯一系统通知身份；90 条来自三次重复恢复补扫，1 条为连接期间新回调。31 个唯一通知全部带 Activity 类型的 `contentIntent`，动作创建方一致。

对每个系统 key 只取一份通知投影后，扫描所有允许复制的可见文本和自定义标量 extras：

| 候选 | 命中通知数 | 结论 |
|---|---:|---|
| `http://` / `https://` / `bilibili://` / `bili://` | 0 | 未观察到持久 URI |
| 合法 `BV` 号语法 | 0 | 未观察到 |
| `av` + 数字语法 | 0 | 未观察到 |
| 自定义标量 extras | 28 | 仅一个字段名 `target_package` |
| `target_package` 值 | 28 | 全部只是包名语法且唯一值相同；不是内容身份 |

Android 标准 extras 只出现标题、正文、样式、进度和媒体会话等字段；没有观察到内容 URI 或结构化内容 ID。`target_package` 只能用于校验来源应用路由或降级入口，不能计为 `PERSISTENT_EXACT_TARGET`。

## 3. 当前分类

- `[已观察]` 当前进程内原始 `PendingIntent`：31/31 唯一通知存在；受控来源与一条真实 B 站通知均已证明原通知移除后可真实落页。
- `[未观察]` B 站持久精确 URI：0/31。
- `[未观察]` B 站结构化内容 ID：0/31。
- `[候选]` B 站当前样本只支持 `RUNTIME_PENDING_INTENT`，进程重建后只能显式降级到打开来源应用。

“未观察”不等于证明所有 B 站通知永远没有持久目标。当前 31 个样本尚未由用户逐条确认投稿、动态、开播类型，且没有覆盖未来 B 站版本；实现必须保留版本化来源提取器入口，但 v0 不得在没有证据时猜测私有路由。

2026-08-23，用户在红魔 11 Pro+ / Android 16 上确认：从系统通知栏划除一条真实 B 站通知后，点击 OMN 中对应归档条目，成功进入预期目标页面。该通知尚未分类为投稿、动态或开播，且成功发生在同一 OMN 进程生命周期内；因此这项结果只把“真实 B 站运行时动作可用”从候选升级为已观察，不证明动作可跨进程或重启恢复，也不替代三类逐项验收。

## 4. 后续必须验证

1. 由用户核对投稿、动态、开播各至少一个真实样本；
2. 对三类分别重复字段白名单扫描，确认是否有类型专属 URI 或 ID；
3. 对投稿、动态和开播分别记录 OMN 明确点击后的派发与实际落页；当前只有一条类型未分类的真实通知通过；
4. OMN 进程重建和设备重启后确认运行时句柄不可恢复，并验证降级文案不冒充精确跳转；
5. B 站更新后重复扫描，避免把当前缺字段外推为稳定平台合同。

真实 B 站样本的同进程运行时闭环已经通过，但跨进程/重启持久目标仍未找到，投稿、动态和开播也尚未逐类确认；因此本 Spike 继续保持候选结论，不能给出完整 `GO`。
