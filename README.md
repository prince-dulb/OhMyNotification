# 救救我的通知！

> Oh My Notification! —— 把被误划掉的 Android 通知捞回来。

“救救我的通知！”是一个本地优先的通知历史工具。它会保存系统交付给它的通知，按应用和时间整理，并在原通知动作仍然有效时尝试带你回到原内容。

不做账号，不做云同步，不上传通知，也不把通知改造成另一套待办清单。

## 为什么做

起因很朴素：我老是手滑划掉 B 站推送，等反应过来，通知已经没了；偏偏手机自己的通知历史又只肯留下最近几条。

试过的现成工具要么漏记、重复和排序混乱，要么只能保存文字、不能回到原内容。既然真正想救的是“那条还能点开的通知”，就干脆自己做一个。

## 能做什么

- 把通知保存在本机，系统通知被划掉后仍可回来查看。
- 合并同一条通知的后续更新，减少重复记录。
- 按稳定时间线排列通知；连续出现的同一应用会收进一个默认展开的小抽屉。
- 按一个或多个应用筛选记录，也可以停止记录指定应用。
- 分别控制媒体、消息与通话、提醒与导航、持续运行与进度等通知类型；媒体通知默认关闭。
- 在通知栏常驻一张低打扰状态卡，显示监听是否正常和最近记录摘要。
- 删除单条历史记录，不影响该应用之后的通知监控。

## 安装后怎么用

1. 安装并打开应用。
2. 按页面提示开启“通知使用权”。这是记录通知所必需的系统权限。
3. 允许应用发送通知。这个权限只用于显示 OMN 自己的常驻状态卡。
4. 看到通知栏里的 OMN 状态卡后即可离开应用；之后收到的新通知会自动进入时间线。

应用抽屉标题右侧的菜单用于管理整个来源：

- **不要再记录此 App**：以后不再保存该应用的新通知，已有历史保留。
- **仅查看此 App**：暂时只看这个应用，不改变后台监控范围。
- **不查看此 App**：从当前列表隐藏这个应用，不停止记录。

更多通知类型、抽屉时间间隔、来源排除和“当前无跳转动作归档”都在设置页中。

## 关于“打开原内容”

OMN 保存的是来源应用放进通知里的 Android 动作，而不是自己猜一个链接。因此，通知被划掉后仍然可能成功回到对应视频、动态或消息；但这个能力不能保证永久有效。

以下情况可能导致跳转失效：

- 来源应用主动取消了动作；
- OMN 或来源应用的进程重建后，系统没有重新提供该动作；
- 原内容已经删除、失效或需要重新登录；
- 来源应用本身只提供了打开首页的通知动作。

当前没有可用动作的记录会进入“当前无跳转动作归档”。你可以在那里要求 OMN 重扫一次系统当前仍活动的通知；找不到同一条通知时，OMN 不会假装成功，也不会擅自打开应用首页。

## 数据与隐私

- 没有网络权限、遥测、广告或远程账号。
- 通知内容、设置和运行时动作只保存在设备本地。
- 不读取联系人、账号或其他应用的私有数据。
- 卸载应用会删除本地通知历史；v1 暂无导出和恢复功能。

## 已知边界

- 目前只支持 Android 16 及以上。
- Android 厂商的后台管理仍可能中断通知监听；OMN 无法为自己保活，请手动设置电池优化项或后台锁定等保活操作。
- 跳转依赖来源通知提供的动作，OMN 无法为没有精确目标的通知制造可靠链接。
